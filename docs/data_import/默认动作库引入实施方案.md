## 1. 首批完成定义（已实施）

首批实现采用以下完成条件；它们构成扩展批次不得破坏的当前基线：

1. [已批准决策] 用 `candidates.md` 的 43 个 A 级和 20 个 B 级动作一次性替换当前 18 个手写内置测试动作；A/B 等级不进入运行时字段。
2. [已批准决策] 不迁移、合并、重定向或保留旧内置测试目录。实现后从空 IndexedDB、空 Android Studio 虚拟机数据和空隔离 WebDAV 目录验收。
3. [已批准决策] 每条动作只有一个 `recordingMode`；记录语义不同就是不同动作，不增加多模式集合或模板覆盖。`loadBasis`、`loadDirection`、`rateMetric` 必须逐条显式策展，不能从器械推断。
4. [已批准决策] `ExerciseDoc` 增加独立 `equipment` 字段和一个可选只读 `provenance` 对象；provenance 不进入前端 DTO 或页面。
5. [已批准的后续扩展] `DefaultExerciseSeed.provenance` 将改为可选：有上游来源的内置动作继续写入完整来源对象，无上游的已批准自编内置动作省略它；不得用近似动作或空值伪造来源。
6. [已批准决策] 中文说明全部进入 `description`，内部换行原样保存和显示；不增加 `instructionStepsZh`、Media 或非中文说明字段。
7. [实施要求] 默认数据不是再次手抄的数组：`candidates.md` 是唯一生成源，必须完整保存生成字段；生成脚本只从该文件产出纯 TypeScript 默认目录，并用固定上游版本校验来源 ID、分类和器械。内容候选文档只供人工更新该文件时参考。
8. [实施要求] build、全量测试、Android sync、字段零残留检索、360px/412px/横竖屏和 Android WebView 走查全部通过。

首批正式目录只由 `candidates.md` 生成。本文件说明实施与验收；继续扩展时读取《默认动作库内容候选 v2》进行人工审查，再将获批结果完整写回 `candidates.md`。历史对话、旧手写默认动作、内容候选文档和模型记忆都不能在生成时补字段。

## 3. 目标领域契约

P1 第 2.3 节是 `ExerciseDoc` 唯一领域权威。实施目标如下；P2 只记录持久化链路状态。

```ts
type ExerciseCategory =
  | "chest" | "back" | "legs" | "shoulders" | "arms"
  | "core" | "cardio" | "stretch" | "other";

type EquipmentId =
  | "body_weight" | "barbell" | "dumbbell" | "cable" | "machine"
  | "band" | "kettlebell" | "ab_wheel" | "stationary_bike"
  | "jump_rope" | "elliptical" | "stepmill" | "external_weight" | "other";

interface ExerciseProvenance {
  source: string;
  sourceId: string;
  sourceRevision: string;
}

interface ExerciseDoc extends BaseDoc {
  name: string;
  category: ExerciseCategory;
  recordingMode: RecordingMode;
  loadBasis: LoadBasis | null;
  countBasis: CountBasis;
  loadDirection: LoadDirection | null;
  rateMetric: RateMetric;
  equipment: EquipmentId | null;
  description: string | null;
  primaryMuscleGroupIds: MuscleGroupId[];
  secondaryMuscleGroupIds: MuscleGroupId[];
  provenance?: ExerciseProvenance;
  isCustom: boolean;
  replacedByExerciseId: string | null;
}
```

运行时约束：

- 当前正式目录中的内置动作均有上游 `provenance`，其值固定为 `{ source: "hasaneyldrm/exercises-dataset", sourceId: <四位上游 ID>, sourceRevision: <固定 SHA> }`。
- [当前实现] `ExerciseDoc.provenance` 可选，但 `DefaultExerciseSeed.provenance` 为必填；因此现有生成链只能生成有上游来源的正式目录。
- [已批准的后续扩展] 将 `DefaultExerciseSeed.provenance` 改为可选，并在字段契约矩阵、core 模型、生成器、测试和本方案同步落地。变更后：有来源的内置动作必须带完整且唯一的来源；已批准自编内置动作必须省略该对象；不得伪造来源、使用空字符串或让页面 DTO 读取它。
- 自定义动作没有 provenance；create/update payload 不接受该字段。core/persistence 的 `ExerciseDoc` 可以保存 provenance，但页面使用的 `Exercise`、`ExerciseDetail` 和列表/搜索/筛选 DTO 必须由显式白名单 mapper 构造，运行时对象也不得含有该 key，而不只是“不渲染”。repository 更新必须从已存 `ExerciseDoc` 合并受控 patch，不能由页面 DTO 重建整条文档而丢失 provenance。
- `equipment` 是产品字段：内置动作由映射生成，自定义动作可在共享表单单选，列表、详情和选择器可显示与筛选。
- `description` 是一个字符串。`candidates.md` 正文中的 `↵`/`↵↵` 转成 `\n`/`\n\n`；状态文字不进入字段。trim 后为 1–500 字符或 `null`，内部换行不压平。候选允许单段压缩说明；默认跑步条目实际包含 `↵` 以验收内置说明分段，`↵↵` 由专用 fixture 验证，不得从上游步骤自动拼接。
- `category` 不含 `compound`。本轮不增加 `movementPattern`。
- `primaryMuscleGroupIds` 最多 3 个，`secondaryMuscleGroupIds` 最多 6 个；组内唯一、主次不交叉、枚举合法。
- [当前 schema 边界] 本轮直接升级到 schema 5，只支持“存储不存在”的首次初始化；v4 及其他旧开发快照均明确拒绝，不迁移、不静默丢弃，也不由应用自动清除。
- [扩展批次前置条件] 未来开始扩展实施时，必须以当时 schema 和五项记录配置重新评估，不得机械套用历史字段形状。
- [已批准的扩展契约] 当前代码的 `EquipmentId` 尚无 `trap_bar`。实施六角杠硬拉或六角杠农夫行走前，必须先在 P1 字段契约矩阵登记该受控枚举扩展，再同步 core 枚举、中文标签、生成映射、service 校验和测试；它不新增 `ExerciseDoc` 属性。
- [记录边界] 当前不设左右侧字段；`per_hand` 只说明每手重量，`per_side` 说明一次录入代表每侧完成且聚合按两侧计入。单侧农夫/手提箱行走若未来另行批准入库，应采用 `total + per_side` 的稳定约定；不得增加侧别字段、左右拆组或独立历史。本轮不新增该动作。

自定义动作写入契约必须明确区分 `undefined` 与 `null`：

```ts
interface CreateExerciseInput {
  name: string;
  category: ExerciseCategory;
  recordingMode: RecordingMode;
  loadBasis: LoadBasis | null;
  countBasis: CountBasis;
  loadDirection: LoadDirection | null;
  rateMetric: RateMetric;
  equipment: EquipmentId | null;
  description: string | null;
  primaryMuscleGroupIds: MuscleGroupId[];
  secondaryMuscleGroupIds: MuscleGroupId[];
}

interface UpdateExerciseInput {
  name?: string;
  category?: ExerciseCategory;
  recordingMode?: RecordingMode;
  loadBasis?: LoadBasis | null;
  countBasis?: CountBasis;
  loadDirection?: LoadDirection | null;
  rateMetric?: RateMetric;
  equipment?: EquipmentId | null;
  description?: string | null;
  primaryMuscleGroupIds?: MuscleGroupId[];
  secondaryMuscleGroupIds?: MuscleGroupId[];
}
```

create 必须显式提供合法的五项记录配置，不能因遗漏回退到某个已有模式；未设置 equipment/description 时页面提交 `null`。update 中 `undefined` 表示不修改，`null` 只用于显式清空允许清空的字段。两种输入都不包含 provenance、ID 或 BaseDoc 元字段。

### 4.4 记录方式与负重配置

六种 `RecordingMode` 的字段、完成规则和合法组合以 P0/P1 注册表为唯一权威。候选表逐条显式保存 `recordingMode/loadBasis/loadDirection/rateMetric`；上游 `cardio` 只表示来源分类，器械也不决定重量口径。普通负重使用 `higher_better`，辅助引体使用 `lower_better`；不含重量的模式两项负重配置均为 null。未来若需要另一记录语义，新增独立动作 ID，不修改同一动作的历史配置。

## 6. 生成与代码结构

推荐新增：

```text
ironlog/frontend/scripts/exerciseCatalog.mjs
ironlog/frontend/src/core/defaultExercises.generated.ts
```

`exerciseCatalog.mjs` 使用 Node 内置模块，不新增运行时依赖，提供：

- `npm run catalog:generate`：读取 `docs/data_import/candidates.md`，从固定 commit 的上游 JSON 在内存中核对记录，生成纯 TypeScript 数组。
- `npm run catalog:check`：不联网，重新解析 `docs/data_import/candidates.md` 并核对已提交产物中的候选哈希、数量、稳定 ID、上游 ID 和字段约束；build/test 前运行。

生成文件头必须包含候选文件哈希、上游 commit 和“禁止手改”提示，不写每次运行都会变化的生成时间，保证同一输入得到相同产物。生成文件输出 `DefaultExerciseSeed[]`，只包含 `id`、名称、category、五项记录配置、equipment、description、主次肌群和**可选** provenance；有上游来源的行输出完整 provenance，已批准自编行省略该键。不得伪装成已经具备 BaseDoc 元字段的 `ExerciseDoc[]`，也不得包含评分、A/B 等级、上游英文说明、其他语言、媒体或完整原始记录。

`defaultData.ts` 使用现有固定 `seedTime = "2026-01-01T00:00:00.000Z"` 将每条 seed 唯一地补成 `ExerciseDoc`：`createdAt=updatedAt=seedTime`、`deletedAt=null`、`schemaVersion=CURRENT_SCHEMA_VERSION`、`isCustom=false`、`replacedByExerciseId=null`。禁止调用当前时间生成默认元字段；同一候选文件和代码版本必须得到字节级稳定的默认目录。

## 7. 首批分阶段实施（已完成）

| 阶段 | 目标 | 预计修改文件 | 数据风险 | 自动验证 | 必须人工确认 |
