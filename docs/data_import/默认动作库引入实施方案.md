## 1. 完成定义

本轮实现完成时必须同时满足：

1. [已批准决策] 用 `candidates.md` 的 42 个 A 级和 20 个 B 级动作一次性替换当前 18 个手写内置测试动作；A/B 等级不进入运行时字段。
2. [已批准决策] 不迁移、合并、重定向或保留旧内置测试目录。实现后从空 IndexedDB、空 Android Studio 虚拟机数据和空隔离 WebDAV 目录验收。
3. [已批准决策] 每条动作只有一个 `type`；记录语义不同就是不同动作，不增加 `supportedTypes` 或模板覆盖。
4. [已批准决策] `ExerciseDoc` 增加独立 `equipment` 字段和一个可选只读 `provenance` 对象；provenance 不进入前端 DTO 或页面。
5. [已批准决策] 中文说明全部进入 `description`，内部换行原样保存和显示；不增加 `instructionStepsZh`、Media 或非中文说明字段。
6. [实施要求] 默认数据不是再次手抄的数组：`candidates.md` 是策展输入，生成脚本核对固定上游版本并产出纯 TypeScript 默认目录。
7. [实施要求] build、全量测试、Android sync、字段零残留检索、360px/412px/横竖屏和 Android WebView 走查全部通过。

本文件与 `candidates.md` 足以启动新 session。历史对话、当前手写默认动作和模型记忆均不是候选或字段事实来源。

## 3. 目标领域契约

P1 第 2.3 节是 `ExerciseDoc` 唯一领域权威。实施目标如下；P2 只记录持久化链路状态。

```ts
type ExerciseCategory =
  | "chest" | "back" | "legs" | "shoulders" | "arms"
  | "core" | "cardio" | "stretch" | "other";

type EquipmentId =
  | "body_weight" | "barbell" | "dumbbell" | "cable" | "machine"
  | "band" | "kettlebell" | "ab_wheel" | "stationary_bike"
  | "jump_rope" | "elliptical" | "stepmill" | "external_weight" | "other";

interface ExerciseProvenance {
  source: string;
  sourceId: string;
  sourceRevision: string;
}

interface ExerciseDoc extends BaseDoc {
  name: string;
  category: ExerciseCategory;
  type: ExerciseType;
  equipment: EquipmentId | null;
  description: string | null;
  primaryMuscleGroupIds: MuscleGroupId[];
  secondaryMuscleGroupIds: MuscleGroupId[];
  provenance?: ExerciseProvenance;
  isCustom: boolean;
  replacedByExerciseId: string | null;
}
```

运行时约束：

- 内置动作 `provenance` 固定为 `{ source: "hasaneyldrm/exercises-dataset", sourceId: <四位上游 ID>, sourceRevision: <固定 SHA> }`。
- 自定义动作没有 provenance；create/update payload 不接受该字段。core/persistence 的 `ExerciseDoc` 可以保存 provenance，但页面使用的 `Exercise`、`ExerciseDetail` 和列表/搜索/筛选 DTO 必须由显式白名单 mapper 构造，运行时对象也不得含有该 key，而不只是“不渲染”。repository 更新必须从已存 `ExerciseDoc` 合并受控 patch，不能由页面 DTO 重建整条文档而丢失 provenance。
- `equipment` 是产品字段：内置动作由映射生成，自定义动作可在共享表单单选，列表、详情和选择器可显示与筛选。
- `description` 是一个字符串。`candidates.md` 正文中的 `↵`/`↵↵` 转成 `\n`/`\n\n`；状态文字不进入字段。trim 后为 1–500 字符或 `null`，内部换行不压平。候选允许单段压缩说明；默认跑步条目实际包含 `↵` 以验收内置说明分段，`↵↵` 由专用 fixture 验证，不得从上游步骤自动拼接。
- `category` 不含 `compound`。本轮不增加 `movementPattern`。
- `primaryMuscleGroupIds` 最多 3 个，`secondaryMuscleGroupIds` 最多 6 个；组内唯一、主次不交叉、枚举合法。
- 开始实施时必须先断言当前 `CURRENT_SCHEMA_VERSION` 仍为 2；若已变化则停止并重新评估版本号，禁止机械写死为 3。前置条件满足时更新为 3，只支持“存储不存在”的首次初始化。读取到任何 schemaVersion 非 3 的已有快照（无论数组是否为空）都必须返回明确的“不兼容开发快照，请按运行指南清理测试存储”错误；不得迁移、合并或静默丢弃，更不得自动清除设备/远端数据。清理后由空存储创建 v3 新快照。

自定义动作写入契约必须明确区分 `undefined` 与 `null`：

```ts
interface CreateExerciseInput {
  name: string;
  category: ExerciseCategory;
  type: ExerciseType;
  equipment: EquipmentId | null;
  description: string | null;
  primaryMuscleGroupIds: MuscleGroupId[];
  secondaryMuscleGroupIds: MuscleGroupId[];
}

interface UpdateExerciseInput {
  name?: string;
  category?: ExerciseCategory;
  type?: ExerciseType;
  equipment?: EquipmentId | null;
  description?: string | null;
  primaryMuscleGroupIds?: MuscleGroupId[];
  secondaryMuscleGroupIds?: MuscleGroupId[];
}
```

create 必须显式提供唯一 `type`，不得因遗漏暗中回退为 `strength`；未设置 equipment/description 时页面提交 `null`。update 中 `undefined` 表示不修改，`null` 只用于显式清空 equipment/description。两种输入都不包含 provenance、ID 或 BaseDoc 元字段。

### 4.4 type

| type | 唯一记录语义 | 策展边界 |
|---|---|---|
| `strength` | 外部负重 + 次数 | 可用 kg/lb 表达的自由重量、绳索和固定器械 |
| `reps_only` | 仅次数 | 动态自重、辅助引体和不记录弹力带张力的动作 |
| `static_hold` | 保持时间 | 侧平板等静态保持 |
| `cardio` | 距离和/或持续时间 | 跑步、跳绳和心肺器械 |

候选表 type 是最终权威。跳绳固定 `cardio`；波比、登山跑和弹力带帕洛夫固定 `reps_only`。未来若需要另一记录语义，新增独立动作 ID，不修改本模型。

## 6. 生成与代码结构

推荐新增：

```text
ironlog/frontend/scripts/exerciseCatalog.mjs
ironlog/frontend/src/core/defaultExercises.generated.ts
```

`exerciseCatalog.mjs` 使用 Node 内置模块，不新增运行时依赖，提供：

- `npm run catalog:generate`：读取 `docs/data_import/candidates.md`，从固定 commit 的上游 JSON 在内存中核对记录，生成纯 TypeScript 数组。
- `npm run catalog:check`：不联网，重新解析 `docs/data_import/candidates.md` 并核对已提交产物中的候选哈希、数量、稳定 ID、上游 ID 和字段约束；build/test 前运行。

生成文件头必须包含候选文件哈希、上游 commit 和“禁止手改”提示，不写每次运行都会变化的生成时间，保证同一输入得到相同产物。生成文件输出 `DefaultExerciseSeed[]`，只包含 `id`、名称、category、type、equipment、description、主次肌群和 provenance；不得伪装成已经具备 BaseDoc 元字段的 `ExerciseDoc[]`，也不得包含评分、A/B 等级、上游英文说明、其他语言、媒体或完整原始记录。

`defaultData.ts` 使用现有固定 `seedTime = "2026-01-01T00:00:00.000Z"` 将每条 seed 唯一地补成 `ExerciseDoc`：`createdAt=updatedAt=seedTime`、`deletedAt=null`、`schemaVersion=CURRENT_SCHEMA_VERSION`、`isCustom=false`、`replacedByExerciseId=null`。禁止调用当前时间生成默认元字段；同一候选文件和代码版本必须得到字节级稳定的默认目录。

## 10. 回滚与上游更新

### 10.1 本轮回滚

当前没有真实数据，回滚是代码回滚加测试环境重建，不提供数据 downgrade：恢复上一版生成产物和契约，清空 Web/AVD/隔离 WebDAV 测试数据后重新初始化。不得为回滚增加双目录兼容、旧字段 fallback 或运行时开关。

首个内部测试版一旦明确作为兼容基线，后续默认目录和字段变更必须重新评估稳定 ID、引用、migration、备份和回滚；本文件的开发期清空例外自动失效。

### 10.3 上游更新

1. 不跟随 `main` 自动更新；显式选择新 commit。
2. 只对 `candidates.md` 中的 upstream id 做字段 diff，同时检查上游删除/重复/翻译变化和许可证文件。

4. 新动作先进入候选表并完成评分，不直接从上游全量灌入。
5. 若上游变更会改变已发布动作语义或稳定 ID，兼容基线后按独立迁移方案处理。
