# IronLog 精选默认动作库引入实施方案

> 状态：当前默认动作目录已实施；后续扩展按兼容基线后的增量流程执行
> 日期：2026-07-16
> 适用阶段：`0.1.0-internal.2` 已建立兼容基线，现有本地或 WebDAV 快照均按可能含用户数据处理
> 已实施目录权威：[candidates.md](candidates.md)
> 第二批已实施证据：[默认动作库内容候选 v2](默认动作库内容候选v2.md)
> 动作评价指南：[训练动作评价指南](训练动作评价指南.md)
> 上游证据与固定 revision：见[默认动作库内容候选 v1](默认动作库内容候选v1.md)和[默认动作库内容候选 v2](默认动作库内容候选v2.md)

## 1. 方案范围

本方案只规定“内容证据完成 → 运行时契约就绪 → 更新唯一生成输入 → 生成 → 兼容迁移与验收”的实施顺序。它不保存逐动作原始事实、内容评价、策展文本或生成字段。

当前 87 条目录已实施：兼容基线前的首批 63 条，以及 schema v8 增量加入的第二批 24 条。该历史状态不授权后续清空、覆盖或拒绝兼容数据。继续扩展时，先在内容候选中完成人工审查，再将获批的完整运行时字段写入 `candidates.md`。历史对话、旧手写默认动作、内容候选文档和模型记忆均不能在生成时补字段。

## 2. 固定输入与停止条件

### 2.1 必须读取

- 根目录及下级适用 `AGENTS.md`。
- `docs/data_import/candidates.md`，包括顶部生成契约及唯一映射表；表中必须自包含生成所需的 ID、来源引用、记录配置、器械、肌群和 description。
- `docs/data_import/训练动作评价指南.md`，确认候选已通过当时适用的准入门与评价审查。
- `docs/概要设计文档.md`、`docs/详细设计文档_P0_核心训练.md`、P1、P2、P3、`docs/如何运行IronLog.md` 和 `docs/部署指南.md`。
- 上游固定 commit 的 `README.md`、`LICENSE`、`NOTICE.md`、`data/exercises.schema.json`、`data/exercises.json`。
- 当前动作全链路：`defaultData.ts`、`models.ts`、`migrations.ts`、页面 DTO、exercise service、mapper、repository、DocumentStore、SyncService、动作/模板/训练/统计页面及测试。

### 2.2 权威输入与停止条件

本方案不保存动作原始事实、内容评价、评分或生成字段。实施时按职责读取：

- `candidates.md`：已实施目录唯一生成输入。
- 内容候选 v1/v2：固定上游证据、内容评价、拟用文本和人工交接参考。
- 《训练动作评价指南》：当前准入门与评价方法。
- P0/P1：记录方式与 `ExerciseDoc` 领域契约。
- P2：当前 schema、migration、稳定 ID 融合和数据保留规则。

固定上游版本、完整原始步骤和许可证证据保存在内容候选文档。当前生成脚本除核对来源记录存在外，还会严格比较分类和器械映射；该检查的通过只能说明脚本条件满足，不能证明最终名称、分类、器械、肌群或 description 与上游语义一致。是否调整该业务代码行为须另行授权，本方案不作决定。出现来源不可读、许可证变化、ID 缺失/重复、候选未完成准入审查或字段契约尚未落地时必须停止实施并报告缺口。

### 2.3 实施前交接

1. 评价指南确认候选可进入实施；A/B 历史标签不进入运行时。
2. 内容候选提供经审查的来源证据与拟用文本。
3. 获批结果完整写入 `candidates.md` 后，生成器不得再从内容候选或其他文档补字段。
4. 若候选需要新枚举、字段或记录语义，先更新 P0/P1 字段契约和 P2 migration，再更新目录。

## 3. 实施依赖摘要

- 动作字段、枚举、引用和自定义动作编辑规则以 P1 为准。
- 组字段、历史快照、记录方式校验和统计口径以 P0 为准。
- schema、默认目录融合、未知字段保留、DocumentStore 与 WebDAV 往返以 P2/P3 为准。
- 本方案只规定跨这些权威的实施顺序和验收门，不复制类型全集、映射表或动作内容。

## 4. data_import 职责与写入顺序

| 文档 | 固定职责 |
|---|---|
| `candidates.md` | 当前默认目录唯一生成输入；完整保存已批准生成字段。 |
| 内容候选 v1/v2 | 来源证据、内容评价、拟用文本和人工交接参考；不参与生成。 |
| 《训练动作评价指南》 | 准入和评分权威。 |
| 本实施方案 | 实施、兼容迁移和验收步骤；不保存动作内容评价或生成字段。 |

写入顺序固定为：评价指南准入 → 内容候选完成人工审查 → P0/P1/P2 契约与 migration 就绪 → 更新 `candidates.md` → 生成与验证。不得反向用生成产物覆盖内容审查，也不得把上游字段或文档搜索命中直接写入正式目录。

## 5. 历史首批导入边界

首批 63 条目录在兼容基线建立前完成。第二批 24 条通过 schema v8 增量加入：19 条引用固定上游记录，5 条自编动作省略 provenance，并新增 `trap_bar` 受控器械枚举。该历史事实只解释当前目录来源，不再授权整体替换、清空快照或删除引用。当前及后续目录变更必须按 P2 的兼容迁移和稳定 ID 融合规则处理；逐动作内容证据和当前评价分别保存在内容候选 v1/v2。

## 6. 当前生成结构

```text
ironlog/frontend/scripts/exerciseCatalog.mjs
ironlog/frontend/src/core/defaultExercises.generated.ts
```

`exerciseCatalog.mjs` 只读取 `candidates.md`，使用 Node 内置模块并提供：

- `npm run catalog:generate`：读取 `docs/data_import/candidates.md`，确认非 `-` 的来源 ID 可在固定 commit 中定位，并按当前代码执行分类与器械映射检查后生成纯 TypeScript 数组；来源 ID 为 `-` 的自编动作跳过上游比对并省略 provenance。该检查不能作为内容评价通过的证据；是否调整检查属于单独的业务代码决策。
- `npm run catalog:check`：不联网，重新解析 `docs/data_import/candidates.md` 并核对已提交产物中的候选哈希、数量、稳定 ID、上游 ID 和字段约束；build/test 前运行。

生成文件头必须包含候选文件哈希、上游 commit 和“禁止手改”提示，不写每次运行都会变化的生成时间，保证同一输入得到相同产物。当前生成文件输出 `DefaultExerciseSeed[]`，包含 `candidates.md` 中的完整生成字段；有固定上游来源的动作带 provenance，自编动作必须省略。不得伪装成已经具备 BaseDoc 元字段的 `ExerciseDoc[]`，也不得包含评分、A/B 等级、上游英文说明、其他语言、媒体或完整原始记录。

`defaultData.ts` 使用现有固定 `seedTime = "2026-01-01T00:00:00.000Z"` 将每条 seed 唯一地补成 `ExerciseDoc`：`createdAt=updatedAt=seedTime`、`deletedAt=null`、`schemaVersion=CURRENT_SCHEMA_VERSION`、`isCustom=false`、`replacedByExerciseId=null`。禁止调用当前时间生成默认元字段；同一候选文件和代码版本必须得到字节级稳定的默认目录。

## 7. 当前实施流程

| 阶段 | 本方案规定的动作 | 进入下一阶段的条件 |
|---|---|---|
| 预检 | 核对工作区、当前 schema、版本元数据、migration、固定上游版本和许可证 | 已区分当前代码事实、内容证据与待批准事项 |
| 内容审查 | 按评价指南完成准入；在内容候选中保存来源证据、评价和拟用文本 | 内容结论可追溯，且未写入生成链 |
| 契约准备 | 若涉及持久化语义，先更新 P0/P1 字段契约和 P2 migration | 新旧快照都有显式处理方案 |
| 目录更新 | 将最终获批的完整生成字段写入 `candidates.md` | 生成器不需要读取其他文档补字段 |
| 生成与回归 | 重新生成目录，并执行默认目录、历史引用、序列化和 UI 回归 | 第 8 节验收通过 |
| 交付 | 按 AGENTS.md 执行构建、测试、Android sync、检索和相应走查 | 结果与未覆盖风险已记录 |

不得把兼容基线前的“直接替换目录”流程用于现有快照。目录删除、稳定 ID 变化或字段语义变化必须先在 P2 确定保留、迁移或重定向策略。

## 8. 验收门

### 8.1 目录与内容

- 新快照的内置动作集合与 `candidates.md` 精确一致，生成产物可重复且无手工补字段。
- 内容候选与评价指南不被生成器读取；评分、候选等级、审查备注和媒体元数据不进入运行时目录。
- 来源引用、稳定 ID、生成字段和中文文本符合当前 P0/P1 契约；具体字段约束不在本方案重复定义。
- 验收报告必须区分来源记录存在性、当前脚本的严格映射检查和人工内容评价，不得把任一脚本检查写成最终语义一致证明。

### 8.2 兼容迁移与数据保留

- 覆盖当前 P2 支持的旧 schema 实际字段形状，并验证迁移后写回再读取稳定。
- 默认目录按稳定 ID 融合；保留训练历史、自定义与未知动作、tombstone、嵌套 ID 和未展示字段。
- WorkoutDoc 历史快照不被当前默认动作配置覆盖；删除或重定向不造成悬空引用。
- IndexedDB、Capacitor Filesystem、导入导出和 WebDAV JSON 序列化往返不丢字段。
- 无法识别的数据必须显式阻断并提供可恢复导出，不得静默丢弃或建议清空。

### 8.3 页面与 Android

- 动作库、详情、共享动作表单、训练草稿、模板两入口和相关统计使用迁移后的同一数据契约。
- UI、CSS 或输入控件有变化时，按 AGENTS.md 在 360px、412px 和 Android WebView 走查；纯数据或文档变更不扩大人工走查范围。
- AVD 或真机上的非空数据先备份再验证。不得清除日常应用数据、卸载应用、删除正式凭据或重置正式 WebDAV 目录。

## 9. 回滚与恢复

- 发布前保留可恢复的本地或远端数据副本；代码回滚不得假定文档 schema 可以降级。
- migration 失败时保留原始分片并报告准确 schema、字段形状和失败路径；优先修复显式 migration。
- 只有用户明确指定的可丢弃浏览器数据、测试 AVD 或隔离 WebDAV 目录，才能按运行指南执行定向清理。
- 已发布稳定 ID 或字段语义的回退必须评估历史引用和 WebDAV 合并结果，不得用旧默认目录覆盖现有快照。

## 10. 上游与内容更新

1. 不自动跟随上游 `main`；先在内容候选中记录选定 revision、来源变化、许可证证据、内容评价和拟用文本。
2. 准入与评分只在《训练动作评价指南》定义；个别动作的审查结论保存在对应内容候选。
3. 完成产品与数据契约审批后，才把最终生成字段写入 `candidates.md` 并更新固定 revision。
4. 上游变化不得自动覆盖人工纠正；若会改变已发布动作语义或稳定 ID，必须先制定兼容 migration。

## 11. 实施会话检查清单

1. 读取适用的 `AGENTS.md` 和概要设计中的文档权威矩阵。
2. 以代码、版本元数据和 migration 核对当前 schema 与兼容基线。
3. 按第 2.2 节读取各权威输入，确认没有跨职责补字段。
4. 修改前全文搜索相关稳定 ID、字段、旧文件名和旧权威描述。
5. 完成后按 AGENTS.md 执行与本次变更相称的验证；文档变更另做中文抽查、链接检查和 `git diff --check`。

## 12. 后续扩展边界

未进入 `candidates.md` 的内容候选不属于当前默认目录。候选获批后仍须先满足当前 P0/P1 契约与 P2 兼容迁移要求，再进入生成链；不得从动作名称、器械类型或旧候选评分推断持久化字段。具体候选证据与待决事项保存在内容候选 v2，本方案不复制。
