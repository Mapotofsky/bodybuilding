## 1. 结论

- [已验证事实] 2026-07-16 通过 `git ls-remote` 核对，上游 `main` 当前为 `7455efae41b330c265e7cd4b78dfa848e7ce5ebd`，已不同于项目固定 SHA；本轮全部字段事实仍只取固定 SHA，未切换来源版本。
- [已验证事实] 哑铃卧推、哑铃飞鸟、蝴蝶机夹胸、蝴蝶机反向飞鸟、哑铃后撤弓步、泽奇深蹲、阿诺德推举、地面卷腹、悬垂直腿举腿、六角杠硬拉、哑铃前平举和单臂绳索侧平举都有可追溯的上游记录。
- [已验证事实] 固定版本没有名为 `face pull` 或 `strict press` 的记录。绳索后束划船不包含拉向面部或肩外旋语义；宽握/窄握 military press 也不能代表无握距限定的通用实力推。
- [策展判断] 面拉和实力推保留为没有可靠上游同义记录的自编候选，不借用相似记录或伪造 `provenance`。其 G0 依据是明确的自编契约；已批准的后续 `DefaultExerciseSeed.provenance` 可选化完成前，仍不能写入生成产物。
- [策展判断] 绳索侧平举采用动作边界更清楚的 0192 单臂记录；0178 虽名为通用侧平举，但步骤没有交代双手绳索的交叉或站位配置，不作为默认动作来源。
- [策展判断] 除用户点名动作外，调研中还保留哈克深蹲、哑铃单腿硬拉、杠铃牧师凳弯举和杠铃仰卧臂屈伸；它们没有因被保留为候选而获得实施批准。相扑硬拉、T 杠划船、耸肩等因当前覆盖、记录语义或枚举损失暂缓。
- [已实施] 2133 农夫行走已按 `weight_distance_duration + per_hand + whole_set + higher_better + load_distance_per_time` 进入正式目录；v2 将其定位为“动态负重稳定”的条件主力，具体评价见《训练动作评价指南》。
- [已验证事实] 本轮新增跑步机爬坡走、站姿绳索胸前推、壶铃交替俯卧撑位划船三个有来源候选，以及六角杠农夫行走、单侧农夫行走、哥本哈根支撑三个自编候选；具体 G0–G3 与评分见《训练动作评价指南》。
- [已批准实现前置] 后续代码将把 `DefaultExerciseSeed.provenance` 改为可选，并加入 `trap_bar`；这解除自编项的来源生成前置和六角杠器械前置，但不把当前仓库状态伪称为已实现。单侧农夫行走不再受左右侧独立历史阻塞：若未来单独批准入库，可采用 `total + per_side`，但本轮不新增该动作或侧别字段。

## 2. 证据边界与当前评价

### 2.1 原始文件

本轮重新核对固定版本的 [README](https://github.com/hasaneyldrm/exercises-dataset/blob/118e4bd6b14da6df0e36605d7169b65db18389a4/README.md)、[LICENSE](https://github.com/hasaneyldrm/exercises-dataset/blob/118e4bd6b14da6df0e36605d7169b65db18389a4/LICENSE)、[NOTICE](https://github.com/hasaneyldrm/exercises-dataset/blob/118e4bd6b14da6df0e36605d7169b65db18389a4/NOTICE.md)、[schema](https://github.com/hasaneyldrm/exercises-dataset/blob/118e4bd6b14da6df0e36605d7169b65db18389a4/data/exercises.schema.json) 和 [exercises.json](https://github.com/hasaneyldrm/exercises-dataset/blob/118e4bd6b14da6df0e36605d7169b65db18389a4/data/exercises.json)。只使用中文步骤及非媒体字段；图片、GIF、Media URL、`media_id` 和非中文 instructions 继续排除。

表中严格区分：

- “上游原始事实”逐字记录固定版本的 id、name、category、body_part、equipment、target、muscle_group 和 secondary_muscles。
- “IronLog 映射”是产品分类、唯一记录方式、规范化器械、有限肌群枚举、稳定 ID 和中文名称。
- description 是根据上游中文步骤压缩、规范化或人工纠错后的 IronLog 文本，不冒充原文。
- IronLog 自编项没有 upstream id，也不生成 `source/sourceId/sourceRevision`。

### 2.2 评价交接

本文件不定义筛选模型、评分公式或等级解释。24 个候选与本轮新增的暂缓/近似记录的当前结论，以[《训练动作评价指南》](训练动作评价指南.md#5-现有目录与规划动作的重评)为唯一依据；表中 v1 数值和 A/B 标签仅保留为历史审计记录。未来实施前必须重新确认当时的 G0–G3 准入状态和 `T/P/U/Q=R`，不能沿用旧分数。

## 7. 未来实施的交接规则

`candidates.md` 是已实施目录的唯一生成源；`默认动作库内容候选v1.md` 是当前 63 条动作的内容审查参考。本文件保存尚未提升候选的来源调研、内容评价、拟用 description 和交接规则。两份内容候选文档都只能用于人工更新 `candidates.md`，不参与生成。

未来独立实施批次必须一次完成以下工作：

1. 先按《训练动作评价指南》的 G0–G3 和 `T/P/U/Q=R` 重新审查；只有通过准入且获得单独批准的候选才能写入 `candidates.md`，不预设 24 条、A/B 分布或总数。
2. 对有来源的候选，先在本文件保存固定 upstream id、原始字段、内容评价和拟用中文说明；批准实施后，再把生成所需的 IronLog 映射、器械和最终 description 完整写入 `candidates.md`。器械、记录方式和肌群必须可由当前契约表达。
3. 已批准把 `DefaultExerciseSeed.provenance` 改为可选。实施该契约时，先更新字段契约矩阵、core 模型、生成器、测试和文档；有来源的内置动作仍必须写唯一且可核验的来源，无来源的自编内置动作必须省略该对象，不得填入近似记录或空字符串。
4. 在上述来源契约尚未实际变更前，生成器必须继续断言每个默认动作都有唯一且可核验的 upstream provenance；变更后，生成器应分别断言“有来源对象时三字段非空且唯一”“无来源对象时仅限已批准的自编候选”，不得预先写死未来来源数量。
5. 实施六角杠硬拉或六角杠农夫行走前，先将 `trap_bar` 按字段契约完整接入枚举、标签、映射、service 校验与测试；不得降级映射为 `other`。
6. 单侧农夫行走不得用 `per_hand` 冒充单手负荷；若未来单独批准入库，使用 `total + per_side`，并完成同一 service、统计、快照、WebDAV 往返和 UI 验证。不得引入侧别字段、左右拆组或独立历史；本轮仍不写入 `candidates.md`。
7. 批次批准后，再从实际通过审查的行计算 A/B、总数、稳定 ID、来源数量和相应断言；同步生成器、生成产物、fixture 和状态文档。
8. `0.1.0-internal.2` 兼容基线后的目录提升必须按稳定 ID 增量融合，并保留自定义动作、历史 WorkoutDoc、未知记录、tombstone 和未展示字段；不得通过清理或覆盖旧快照实施。
9. 证明当时目录的稳定 ID 与上游 ID 唯一、description 不超过 500 字、Media 和非中文 instructions 不进入产物、未展示字段原样保存；对任何新增来源契约变更补充 DocumentStore/WebDAV 往返测试。
10. 运行 `npm run catalog:generate`、`npm run catalog:check`、`npm run build`、`npm test`、`npm run test:layout` 和 `npm run android:sync`，再走查动作库搜索、分类/器械筛选、详情、训练/模板选择器及 360px、412px、横竖屏和 Android WebView。
11. 同步 README、概要设计、P1/P2、运行指南和部署指南中的实际目录状态；来源信息仍只用于目录维护与差异审计，前端不显示，也不新增 `movementPattern` 或多记录模式。

## 8. 已定稿内容与停止条件

- [草案] 第 5 节五个自编 description 是待审查文本，不构成运行时接入授权；来源契约解除或器械枚举补齐后仍须按当时证据与字段契约复审。单侧农夫行走不再有侧别 G1 阻塞，但仍须获得独立入库批准。
- [历史事实] `git show 05d7976^:ironlog/frontend/src/core/defaultData.ts` 可核对两个复用 ID 的旧名称、category、历史记录配置、肌群和说明；这些历史内容不构成当前实施批准。
- [停止条件] 实施时若当前 schema、字段契约或固定上游版本与本文不一致，先重新审查并更新迁移方案；不得硬编码本文记录时的历史版本，也不得把候选状态当成入库授权。
