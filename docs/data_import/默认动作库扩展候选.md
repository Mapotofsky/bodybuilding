## 1. 结论

- [已验证事实] 上游 `main` 的当前 HEAD 与项目固定 SHA 相同；本轮没有切换来源版本。
- [已验证事实] 哑铃卧推、哑铃飞鸟、蝴蝶机夹胸、蝴蝶机反向飞鸟、哑铃后撤弓步、泽奇深蹲、阿诺德推举、地面卷腹、悬垂直腿举腿、六角杠硬拉、哑铃前平举和单臂绳索侧平举都有可追溯的上游记录。
- [已验证事实] 固定版本没有名为 `face pull` 或 `strict press` 的记录。绳索后束划船不包含拉向面部或肩外旋语义；宽握/窄握 military press 也不能代表无握距限定的通用实力推。
- [策展判断] 面拉和实力推单列为 IronLog 自编默认动作，不借用相似记录，不写外部 `provenance`。
- [策展判断] 绳索侧平举采用动作边界更清楚的 0192 单臂记录；0178 虽名为通用侧平举，但步骤没有交代双手绳索的交叉或站位配置，不作为默认动作来源。
- [策展判断] 除用户点名动作外，再选入哈克深蹲、哑铃单腿硬拉、杠铃牧师凳弯举和杠铃仰卧臂屈伸；相扑硬拉、T 杠划船、耸肩等因当前覆盖、记录语义或枚举损失暂缓。
- [已实施] 2133 农夫行走已按 `weight_distance_duration + per_hand + higher_better + load_distance_per_time` 进入正式 A 级目录；可记录性从 2 重评为 5，总分由 24 调整为 27。
- [策展判断] 其余 18 个候选继续留在本文件，需在未来独立批次重新核对四项记录配置后才能提升；本轮仍拒绝大量握距、角度和器械微变体。

## 2. 证据边界与评分

### 2.1 原始文件

本轮重新核对固定版本的 [README](https://github.com/hasaneyldrm/exercises-dataset/blob/118e4bd6b14da6df0e36605d7169b65db18389a4/README.md)、[LICENSE](https://github.com/hasaneyldrm/exercises-dataset/blob/118e4bd6b14da6df0e36605d7169b65db18389a4/LICENSE)、[NOTICE](https://github.com/hasaneyldrm/exercises-dataset/blob/118e4bd6b14da6df0e36605d7169b65db18389a4/NOTICE.md)、[schema](https://github.com/hasaneyldrm/exercises-dataset/blob/118e4bd6b14da6df0e36605d7169b65db18389a4/data/exercises.schema.json) 和 [exercises.json](https://github.com/hasaneyldrm/exercises-dataset/blob/118e4bd6b14da6df0e36605d7169b65db18389a4/data/exercises.json)。只使用中文步骤及非媒体字段；图片、GIF、Media URL、`media_id` 和非中文 instructions 继续排除。

表中严格区分：

- “上游原始事实”逐字记录固定版本的 id、name、category、body_part、equipment、target、muscle_group 和 secondary_muscles。
- “IronLog 映射”是产品分类、唯一记录方式、规范化器械、有限肌群枚举、稳定 ID 和中文名称。
- description 是根据上游中文步骤压缩、规范化或人工纠错后的 IronLog 文本，不冒充原文。
- IronLog 自编项没有 upstream id，也不生成 `source/sourceId/sourceRevision`。

### 2.2 评分口径

本文件全部分数采用[《默认动作库引入实施方案》第 2.3 节](默认动作库引入实施方案.md#23-筛选与评分权威v1)的 v1 指标、公式、等级建议区间和硬性排除规则，不在本文件另设口径。表格中的七段分数顺序及 A/B 例外均按该权威解释。

## 7. 实施时的提升规则

当前 `candidates.md` 是生成器的整文件哈希输入；即使新增行不被解析，只改它也会使已提交生成产物失配。因此本轮把待实施内容保存在本文件，不修改当前生成目录。`candidates.md` 顶部“后续增删只修改本文件”仍约束已提升的正式目录；本文件属于提升前调研，实施合并后必须恢复单一正式权威。

下一轮实施必须一次完成：

1. 未来独立批次若批准，才将其余 16 个上游候选和 2 个自编候选并入 `candidates.md`；在当前 A43/B20/63 基线上全部加入后为 A47、B34、共 81 个。合并后完整正式字段只能保留在 `candidates.md`。
2. 严格使用实施方案第 12.2 节的六列表语法和唯一自编标记 `` `IronLog 自编`<br>无 upstream；provenance `none` ``。来源行的 E 必须与 upstream 派生 equipment 一致；自编行必须显式提供并校验 E，不得伪造 `sourceId`。
3. `DefaultExerciseSeed.provenance` 与 `ExerciseDoc.provenance?` 均保持可选。未来实施前必须以当时 schema 和四项记录配置重新评估，不得沿用 v3 假设或跳过契约矩阵。
4. 生成器只对带 provenance 的 78 个动作执行 upstream id 唯一性和原始字段核对；同时断言恰有 2 个无 provenance 的内置动作，且 ID 只能是 `ex-overhead-press`、`ex-face-pull`。
5. `upper chest → chest` 保持为人工策展规则；本批只为阿诺德推举增加原值与映射结果的定点断言，不引入无法表达人工纠错/忽略的通用肌群合成算法。继续执行 D1 去重、主次不交叉、主肌群最多 3 个、次肌群最多 6 个和枚举合法性检查。
6. 更新生成器、生成产物、当前目录数量测试和状态文档中的 A43/B20/63；删除 retired-ID 断言中的 `ex-overhead-press`、`ex-face-pull`，仍保证 `ex-squat`、`ex-plank`、`ex-cat-cow-stretch` 不出现。
7. 当前合法 v4 快照不会自动与 `DEFAULT_EXERCISES` 合并。兼容基线前按运行指南只清理隔离 Web、Android Studio AVD 和测试专用 WebDAV 数据，再以 81 个动作重新初始化；不新增默认数据增量合并、redirect 或 migration。
8. 证明 81 个稳定 ID 唯一、description 不超过 500 字、Media 和非中文 instructions 不进入产物、未展示字段原样保存；DocumentStore/WebDAV mock 自动往返后两个自编对象仍没有 own `provenance` key，Web 与 AVD 分别人工验证 IndexedDB/Capacitor Filesystem 空初始化。
9. 运行 `npm run catalog:generate`、`npm run catalog:check`、`npm run build`、`npm test`、`npm run test:layout` 和 `npm run android:sync`，再走查动作库搜索、分类/器械筛选、详情、训练/模板选择器及 360px、412px、横竖屏和 Android WebView。
10. 同步 README、概要设计、P1/P2、运行指南和部署指南中的当前数量；来源信息仍只用于目录维护与差异审计，前端不显示，也不新增 `movementPattern` 或多记录模式。按实施方案同步三份 data_import 文档的状态，并把本文件的完整字段表收敛为提升审计清单。
