# P2 详细设计文档：本地文档存储与数据迁移

> 对应概要设计：M3 本地存储、迁移与同步中的本地持久化部分；M5 主题设置；M6 AI 非敏感配置
> 状态：当前本地存储基线；精选动作目录的字段与直接替换策略已批准、待按独立实施方案落地
> 前置依赖：概要设计的数据不变量；P0/P1 的领域文档模型。

---

## 1. 设计目标与边界

本模块在无服务端环境中提供训练、动作、计划、模板、资料和设置的本地真源。它解决三个问题：

1. 同一业务代码在浏览器开发和 Android 上可读写相同 JSON 逻辑文件。
2. JSON 以静态文件与训练月分片保存，不退化为单一巨型文件。
3. 文档格式变化可通过 schemaVersion 归一化，而不是要求页面兼容所有旧字段。

本模块不负责：WebDAV 网络 IO、同步冲突合并、用户可操作的导入/导出 UI、Android Keystore 加密细节。它提供 `DocumentStore`、`SecretStore` 和 `LocalJsonRepository` 的平台边界；Android 加密与升级迁移流程由 P3 定义。

## 2. 文件、快照和 manifest

### 2.1 逻辑文件

| 路径 | 内容 | 更新来源 |
|---|---|---|
| `manifest.json` | 应用标识、schema、设备 ID、分片列表 | 任意 repository mutation 后重建。 |
| `profile.json` | ProfileDoc | 更新本地资料。 |
| `settings.json` | SettingsDoc | 更新可同步偏好，不保存 WebDAV 端点配置。 |
| `exercises.json` | ExerciseDoc[] | 内置/自定义动作、tombstone 与替代重定向。 |
| `templates.json` | `{ plans, templates }` | 计划、模板变更。 |
| `body-metrics.json` | BodyMetricDoc[] | P6 身体指标稀疏测量记录，已实现。 |
| `timeline-notes.json` | TimelineNoteDoc[] | P6 日期/时间段背景备注，已实现。 |
| `workouts/YYYY-MM.json` | WorkoutDoc[] | 该月训练创建、编辑、删除、复制。 |
| `exercise-performance/YYYY-MM.json` | ExercisePerformanceRecordDoc[] | P7 动作成绩刷新事件，已实现。 |
| `assets/avatar/*` | 头像资源文件 | ProfilePage 选择、替换或清除头像。 |

`DataSnapshot.workouts` 是运行时聚合数组。训练的磁盘真源只允许是月分片；不得新增全量 `workouts.json` 或另一份训练索引文件。

### 2.2 IronLogManifest

```ts
interface IronLogManifest {
  app: "ironlog";
  schemaVersion: number;
  deviceId: string;
  updatedAt: string;
  shards: Array<{
    path: string;
    updatedAt: string;
    etag?: string | null;
  }>;
}
```

`buildShardList(snapshot)` 输出六个静态分片、实际存在的训练月分片、动作成绩月分片以及头像资源文件。某月只有 tombstone 训练或成绩事件时，该分片仍必须列出并同步；否则另一设备可能恢复已删除记录。

### 2.3 分片规则

```ts
workoutShardPath("2026-06-22") === "workouts/2026-06.json"
isWorkoutShardPath(path) === /^workouts\/\d{4}-\d{2}\.json$/
```

日期不合法不能用于构造分片路径。当前 service 依赖页面传入 `YYYY-MM-DD`；后续若开放导入，导入层必须在写入前校验日期。

## 3. DocumentStore 平台接口

定义位置：`frontend/src/platform/documentStore.ts`。

```ts
interface SecretStore {
  readSecret(key: string): Promise<string | null>;
  writeSecret(key: string, value: string): Promise<void>;
  removeSecret(key: string): Promise<void>;
}

interface DocumentStore extends SecretStore {
  load(): Promise<Partial<DataSnapshot> | null>;
  save(snapshot: DataSnapshot): Promise<void>;
  readSyncEndpoint(): Promise<SyncEndpointConfig>;
  writeSyncEndpoint(config: SyncEndpointConfig): Promise<void>;
  clearSyncEndpoint(): Promise<void>;
  exportFiles(snapshot: DataSnapshot): Record<string, unknown>;
  importFiles(files: Record<string, unknown>): Partial<DataSnapshot>;
}
```

### 3.1 浏览器实现：IndexedDbDocumentStore

- 使用一个 IndexedDB object store 保存逻辑路径到 JSON 对象的映射。
- manifest 是读取入口；先读 manifest，再读静态文件和其中列出的训练分片。
- 浏览器 secret 当前也保存在 IndexedDB 的独立 key 前缀下，只用于开发兼容，不代表安全凭据库。
- 清理站点数据或隐私模式结束会删除这些数据。

### 3.2 Android 实现：CapacitorDocumentStore

- 使用 Capacitor Filesystem `Directory.Data` 下的 `ironlog-data/`。
- 保存时先写所有非 manifest 分片，再写 manifest，最后删除旧 manifest 中已不存在的训练月分片。
- 读取 JSON 失败当前返回 `null`；这避免应用启动立即崩溃，但也会隐藏损坏原因。后续应增加校验和恢复提示。
- Preferences 保存 URL、用户名和 `passwordRef` 等本机端点配置，并只作为旧版密码迁移源。新密码通过 Android `SecretStore` 写入 Keystore 保护的加密存储；密码、密文和解密材料均不进入 DocumentStore JSON。

### 3.3 平台选择

`createDocumentStore()` 仅在 `window.Capacitor.isNativePlatform()` 为真时选择 Capacitor 实现，否则选 IndexedDB。SecretStore 同样由 platform 层选择：Android 为 Keystore 加密实现，Web 为 IndexedDB 开发实现。业务模块不得自行分支判断平台。

### 3.4 主题与规划中的 AI 设置

当前 SettingsDoc 包含 weightUnit、themeId、lastSyncAt。WebDAV url、username、passwordRef 是本机-only 同步端点配置，通过 DocumentStore 本地配置接口保存；password 明文只能通过 DocumentStore secret 保存。它们不得进入 `settings.json`、manifest、远端 JSON 分片或 backup。themeId 使用稳定 string ID，默认 emerald-slate；未知值由 UI 回退但 migration 和同步不得改写原值。AI 仅保存非敏感 provider/model/能力配置、同意版本及 apiKeyRef；API key 明文只能通过 DocumentStore secret 保存。

首个对外或内部测试兼容基线建立后，新增持久化字段必须递增 schemaVersion，添加显式 migration、读取后写回、DocumentStore export/import 与 WebDAV 往返测试。当前尚无真实数据；经明确批准的开发期字段直接替换只递增当前 schema 并重建测试快照，不为废弃测试格式实现 migration，但仍必须完成 export/import 与 WebDAV 往返测试。远端 settings 的秘密引用清空规则由 P3 扩展，不能只依赖页面默认值。

### 3.5 动作详情元数据

`ExerciseDoc` 的完整领域字段、受控枚举、记录类型、器械、分段 description、肌群和 provenance 只由 P1 第 2.3 节定义。P2 不再重复一份不完整接口，也不把上游 `category/body_part/target/muscle_group` 当作存储模型。

本节只定义持久化边界：`DataSnapshot.exercises` 整体写入 `exercises.json`；IndexedDB、Capacitor Filesystem、DocumentStore export/import 与 WebDAV 必须原样保存所有 `ExerciseDoc` 字段。`description` 仍是一个 `string | null`，其中的 `\n`/`\n\n` 必须原样往返；不增加平行的步骤字段。`provenance` 位于同一文档内但不经过页面 DTO，不能因为 UI 未展示而在 mapper、repository 更新或同步往返中丢失。Media 字段和非中文 instructions 不进入 `DataSnapshot` 或构建产物。

精选目录实施前，当前代码尚无 `equipment` 和 `provenance`，`category` 也仍是任意 string。实施时直接替换现有手写内置测试目录及其 fixture，建立新开发快照；不为旧默认目录、被移除测试动作、旧自定义动作或旧字段形状编写 migration、redirect 或 union 合并。本轮不提供“只保留旧自定义动作”的第三条路径：旧开发快照整体废弃，所有需要继续使用的 fixture 必须按新契约重新定义。

该直接替换规则只适用于首个兼容基线前且已确认没有真实数据的开发阶段。精选目录实现只支持“本地存储不存在”的首次初始化；读到 schemaVersion 不是新版本的任何已有快照时必须停止加载并返回可操作的“不兼容开发快照”错误，不迁移、不合并、不静默丢弃，也不由应用自动清空。开发者按运行指南人工清空浏览器 IndexedDB、Android 虚拟机应用数据及隔离测试 WebDAV 目录后重试；不能在日常真机或正式远端目录执行清空。兼容基线建立后，任何字段或默认目录演进都必须另行设计 migration、备份和回滚。

生成目录采用确定性两段式：生成文件只输出不含 BaseDoc 元字段的 `DefaultExerciseSeed[]`；`defaultData.ts` 使用固定 `seedTime = "2026-01-01T00:00:00.000Z"` 补齐 `createdAt`、`updatedAt`，并固定写入 `deletedAt=null`、`schemaVersion=CURRENT_SCHEMA_VERSION`、`isCustom=false`、`replacedByExerciseId=null`。默认元字段不得调用当前时间，保证同一输入产物稳定。

### 3.6 头像资源

`ProfileDoc.avatarUrl` 保存头像资源路径引用，例如 `assets/avatar/profile-local.txt`，不保存 base64 正文。头像正文由 DocumentStore 作为资源文件保存；Web 端和 Android 端均通过同一 service 读取为 data URL 预览。ProfilePage 选择或替换头像时先写入资源文件，再把 profile 引用改为该路径；清除头像时将 `avatarUrl` 置为 null 并删除旧资源。

头像资源必须进入 manifest shards，并随 P3 同步流程 tmp/MOVE 发布。远端已有头像资源在覆盖前写入 `backups/`；清除头像后，下一次同步根据新 manifest 删除远端过期头像资源。profile 与资源文件的边界是：profile 只保存引用，资源正文不进入 `profile.json`、`settings.json` 或训练分片。当前工程先实现 Web 文件选择和本地资源接口；若 Android WebView 的文件选择能力受设备限制，后续再增加 Capacitor 原生选择器适配。

### 3.7 规划中的批准计划批量导入

当前 createPlan、createTemplate、createExercise 是独立 mutation，不能满足 AI 导入的原子性要求。P2 只定义并实现 repository 批量提交原语：在 snapshot 副本上应用已验证的变更、一次保存、成功后替换正式 snapshot，失败则保持正式 snapshot 不变。候选 JSON 校验、未知动作决议、预览、导入业务顺序和回滚规则由 P5 权威定义。

## 4. LocalJsonRepository

文件：`frontend/src/repositories/localJsonRepository.ts`。

### 4.1 初始化

```text
getSnapshot()
  -> DocumentStore.load()
  -> makeEmptySnapshot(deviceId)（空存储时）
  -> migrateSnapshot(raw, deviceId)
  -> DocumentStore.save(snapshot)
```

设备 ID 用 `localStorage` 中的 `ironlog_device_id` 保存；在 Android WebView 中它仅用于 manifest 标识，不是账户标识。

### 4.2 CRUD 规则

| 操作 | Repository 行为 |
|---|---|
| create | `withDoc` 生成 string ID、createdAt、updatedAt、deletedAt=null、schemaVersion=`CURRENT_SCHEMA_VERSION`。 |
| update | `withoutUndefined` 后合并；`undefined` 不覆盖旧字段；更新 `updatedAt`。 |
| delete | `tombstone` 写 `deletedAt` 和 `updatedAt`。 |
| list/get | 默认过滤 tombstone；需要历史/同步时显式 `includeDeleted`。 |
| mutate | 更新 manifest.updatedAt，重建 manifest.shards，调用 DocumentStore.save。 |

训练创建/更新还有额外规则：若嵌套动作或组 ID 为 `""`，repository 生成新 ID。复制训练必须显式把来源嵌套 ID 置空，不能只复制数组引用。

### 4.3 原子性限制

当前 repository 是内存快照 + 全量相关分片写入模型；它没有跨文件事务或本地临时文件发布。一次写入中断时可能留下部分新分片和旧 manifest。当前恢复策略是以 manifest 为读取入口；后续要提高可靠性时，应引入本地临时文件、校验和或写入日志，而不是在页面中补偿。

## 5. schema migration

文件：`frontend/src/core/migrations.ts`。

### 5.1 当前行为

`CURRENT_SCHEMA_VERSION = 2`。`migrateSnapshot` 的职责是：

1. 创建完整默认快照。
2. 合并可读取的 raw snapshot。
3. 对 profile/settings/数组文档补齐 BaseDoc 元字段。
4. 当前代码按内置动作固定 ID 增量合并 `DEFAULT_EXERCISES`：空库写入完整默认库；非空库补齐缺失内置动作，并以代码定义修正同 ID 内置动作的受控分类和 type。该行为是待精选目录导入时删除的旧实现事实，不是新目录兼容要求。
5. 为历史 `WorkoutExerciseDoc` 补齐 `exerciseType`：优先保留已有合法快照，其次读取关联动作的当前 type，最后依据已有组中的距离/时长字段推断；归一化后写回本地和同步分片。
6. 丢弃旧 `ProfileDoc.height` / `ProfileDoc.weight` 测试字段，初始化 `bodyMetrics`、`timelineNotes` 和 `exercisePerformanceRecords`。
7. 重新计算 manifest.shards。

自定义动作不参与默认数据覆盖。历史数据中的 `ExerciseDoc.replacedByExerciseId` 缺失时归一化为 `null`；该字段与 tombstone 一起保留在 exercises.json，供其他设备和读取侧解析动作替代链。

这是一种“归一化 v2”而非可追溯的多版本迁移链。当前分支明确不迁移历史 FastAPI/PostgreSQL 数据或旧的大训练索引数据。由于尚未建立内部测试兼容基线且不存在真实数据，精选动作目录实施时不保留这套旧默认动作的 union/增量补齐行为：新快照的内置动作必须与精选目录精确一致，旧开发快照按运行指南清理。

### 5.2 开发期动作目录替换与兼容基线后的迁移

精选动作目录属于已批准的开发期直接替换：

1. 先更新 P1 领域契约和本节持久化矩阵，再修改模型与代码。
2. 实施前断言代码中的 `CURRENT_SCHEMA_VERSION` 仍为 2；若不是 2，停止并重新选择版本号，不得直接照抄计划中的 3。
3. 前置条件满足时把 schema 设为 3，用 `candidates.md` 的 A/B 精选集合整体替换手写内置测试动作；旧内置动作不参与 union，不为淘汰项创建 tombstone 或 redirect。
4. 同步替换默认模板、测试 fixture 和所有硬编码引用；新快照不得存在悬空 ID。
5. 删除旧 schema/default 归一化路径。仅当 DocumentStore 判断本地存储不存在时创建 v3；`migrateSnapshot` 或等价读取边界收到任何非 v3 已有快照时返回明确的开发快照不兼容错误，不得转换、合并、丢弃或触发清除操作。
6. 开发者确认目标是浏览器测试数据、指定 Android Studio 虚拟机和隔离测试 WebDAV 目录后人工清空，再从不存在的存储初始化。不得把日常真机或正式远端数据当作可清空测试数据。

首个兼容基线建立后，当 `schemaVersion` 再次增加时才必须：

1. 在 `models.ts` 定义新字段和默认/空值语义。
2. 新增显式 migration 分支，例如 `v1 -> v2`，不能仅靠对象展开。
3. 同时迁移静态文件和 workout 月分片。
4. 保留 tombstone 与未知字段的兼容策略。
5. 添加旧快照升级测试、无数据初始化测试和同步后加载测试。
6. 更新 manifest schemaVersion，并在发布说明描述不可逆风险。

精选动作目录不采用兼容 migration 路径；测试必须覆盖 v2 空快照与非空快照都被拒绝、错误信息可指导人工清理，并确认应用本身没有执行删除。人工重置不兼容的 IndexedDB/Android 虚拟机测试快照后，再确认新快照中的 category、type、equipment、description、肌群和 provenance 能随 `exercises.json` 往返。真实用户数据保留方案属于兼容基线后的独立决策，不能把本轮开发期清空规则延伸到未来用户数据。

P6 已直接用 `BodyMetricDoc` 替换旧 `ProfileDoc.height` / `ProfileDoc.weight` 身体数据模型。当前阶段不迁移旧开发/虚拟机测试数据，不在读取层兼容旧字段，也不把旧 Profile 单值生成初始身体记录；验证时按运行指南清空 IndexedDB 或 Android 模拟器旧测试数据后重建。这个规则只适用于当前开发测试阶段，不能作为面向真实用户发布的数据保留策略。

### 5.3 导入/导出边界

DocumentStore 已提供 `exportFiles` / `importFiles` 辅助函数，用于把 snapshot 转为逻辑文件集合或反向解析。当前没有用户 UI、文件选择器、完整格式校验或覆盖确认流程；不得在文档中宣称“已提供数据导入导出”。

后续导入流程至少要：校验 manifest、校验路径白名单、执行 migration、显示将覆盖/合并的文档数量、创建本地备份，再调用 `replaceSnapshot`。
