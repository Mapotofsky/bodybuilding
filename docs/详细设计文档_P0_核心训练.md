# P0 详细设计文档：核心训练与动作记录

> 对应概要设计：M1 核心训练与历史解释兼容性
> 状态：当前实现基线；个人动作统计已接入动作详情；主题与 AI 路线不得破坏本模块的数据契约。
> 前置依赖：P2 本地文档存储与迁移。P1 模板与日历只通过 `planTemplateId` 与本模块关联。

---

## 1. 目标、边界与不变量

本模块在没有网络、账户、后端或 WebDAV 配置的情况下，完成训练创建、逐组记录、草稿恢复、编辑、复制、删除、动作历史和训练详情分享数据派生。

本模块不负责：远端同步、模板编排、用户认证、云端分析、主题选择、AI 请求或联网检索。页面不能直接读写 JSON 或平台文件；所有读写必须通过 service 和 LocalJsonRepository。主题只能改变呈现；未经用户确认的 AI 候选不得创建、更新或覆盖 WorkoutDoc。

核心不变量：

1. `WorkoutDoc` 是完整训练聚合，内嵌动作和组。
2. workout、动作条目和组条目都使用新的 string ID；复制训练不能复用嵌套 ID。
3. 删除训练写 tombstone，常规列表和统计不显示 tombstone。
4. 单位、休息秒数、模板关联在创建、保存、读取、编辑和复制链路中不能丢失。
5. 训练创建页的模板入口有 URL 参数和页内选择器两条，P1 规定的过滤行为必须保持。
6. `endTime=null` 的训练是未结束草稿；恢复或结束草稿均不得丢失已保存的动作和组。
7. `WorkoutExerciseDoc` 保存 `recordingMode`、`loadBasis`、`countBasis`、`loadDirection`、`rateMetric`、`contextKind` 六项训练时快照；动作替代或后续编辑不能改变历史训练的录入规则、显示和统计解释。

## 2. 持久化模型

### 2.1 WorkoutDoc

定义位置：`frontend/src/core/models.ts`。

```ts
interface WorkoutDoc extends BaseDoc {
  date: string;                         // YYYY-MM-DD
  startTime: string | null;             // ISO 8601
  endTime: string | null;               // ISO 8601
  planTemplateId: string | null;
  note: string | null;
  mood: number | null;                  // 当前 UI 使用 1~5
  exercises: WorkoutExerciseDoc[];
}
```

训练按 `date.slice(0, 7)` 写入 `workouts/YYYY-MM.json`。同一月文件包含正常记录和 `deletedAt != null` 的 tombstone；内存 `DataSnapshot.workouts` 只是已加载分片的聚合。

### 2.2 嵌套动作和组

```ts
interface WorkoutExerciseDoc {
  id: string;
  exerciseId: string;
  recordingMode: RecordingMode;
  loadBasis: LoadBasis | null;
  countBasis: CountBasis;
  loadDirection: LoadDirection | null;
  rateMetric: RateMetric;
  contextKind: "none" | "resistance_level" | "incline_percent";
  sortOrder: number;
  supersetGroup: number | null;
  sets: WorkoutSetDoc[];
}

interface WorkoutSetDoc {
  id: string;
  setNumber: number;
  weight: number | null;
  reps: number | null;
  unit: "kg" | "lb";
  durationSec: number | null;
  distanceM: number | null;
  rpe: number | null;
  isWarmup: boolean;
  isFailure: boolean;
  restSeconds: number | null;
  contextValue: number | null;
}
```

`sortOrder` 表示动作在训练内的顺序；`setNumber` 从 1 起连续编号。六项记录配置取自选择动作当时的 `ExerciseDoc` 并固化为历史快照，不表示同一动作可以切换模式；每个动作目录项的唯一配置由 P1 定义。详情、历史、编辑、复制、统计、成绩重建和分享只能按快照解释旧训练，不能读取动作当前配置后覆盖。`countBasis="per_side"` 只表示一次录入覆盖左右两侧的相同训练量；`WorkoutSetDoc` 不新增侧别、左右拆组、独立休息或其他侧别字段。`supersetGroup` 是预留字段，当前 UI 不提供编排，但读取、映射、编辑保存和同步往返不得清空已有值。`contextValue` 只承载当前 `contextKind` 的值；阻力和坡度不会同时存在。聚合编辑必须保留嵌套 ID、未展示字段和同步导入字段。

### 2.3 记录方式注册表与组校验

`frontend/src/core` 中的纯 TypeScript 注册表和负载语义 helper 是唯一权威，集中定义允许字段、显示顺序、`requiredAll`、`requiredOneOf`、数值类型和范围、草稿空值、重量口径、计数口径、竞速指标及成绩生成策略。所有调用方必须按 `RecordingMode` 穷尽处理，新增值不能落入 `unknown`、`else` 或某个既有模式。

| 记录方式 | 字段顺序 | 完成组规则 |
|---|---|---|
| `weight_reps` | `weight`、`reps` | 两项都必填。 |
| `reps` | `reps` | 必填。 |
| `duration` | `durationSec` | 必填。 |
| `distance_duration` | `distanceM`、`durationSec` | 至少一项。 |
| `reps_duration` | `reps`、`durationSec` | 时间必填，次数可选；爬楼机用 `reps` 表达步数，不新增等价字段。 |
| `weight_duration` | `weight`、`durationSec` | 两项都必填。 |
| `weight_distance_duration` | `weight`、`distanceM`、`durationSec` | 重量必填；距离、时间至少一项。 |

草稿允许完全空白的占位组；一旦某字段非空就立即验证有限数值、类型与范围。完成组或完成训练时必须满足上表，service 是最终校验权威。未填写与不适用字段保持 `null`，不得写成伪造的 0；`undefined` 只表示不修改。

### 2.5 页面兼容类型

页面仍使用历史 `snake_case` 类型，例如 `start_time`、`exercise_id`、`rest_seconds`。转换只允许发生在：

```text
pages -> services/workout.ts -> LocalJsonRepository -> WorkoutDoc
                         ^
                   services/localMappers.ts
```

页面不得引用 `WorkoutDoc` 后直接写入 DocumentStore。

## 3. 本地调用契约

### 3.1 Workout service

文件：`frontend/src/services/workout.ts`。

| 函数 | 输入 | 结果 | 规则 |
|---|---|---|---|
| `getWorkouts` | `month` / `from` / `to` | `WorkoutSummary[]` | 默认过滤 tombstone，日期范围为闭区间。 |
| `getWorkout` | `id: string` | `Workout` | 不存在或已删除时抛错。 |
| `getLatestWorkoutDraft` | 无 | `Workout \| null` | 返回最后更新的有效未结束训练（`endTime=null`）。 |

`WorkoutCreatePayload` 的字段必须与 `WorkoutDoc` 的映射成对维护。新增字段时按如下链路检查：

```text
WorkoutCreatePage state
-> buildPayload
-> WorkoutCreatePayload
-> service mapper
-> WorkoutDoc
-> LocalJsonRepository
-> toWorkout / toWorkoutSummary
-> Detail/Edit/List 页面
```

### 3.2 动作引用依赖摘要

动作库浏览、自定义动作 CRUD、删除/替代兼容检查和详情信息呈现由 P1 权威定义。P0 仅依赖有效 ExerciseDoc 选择训练动作，并保证 WorkoutExerciseDoc 的 exerciseId 与六项记录快照可供历史显示和本节统计读取；P0 不定义动作库 UI、动作元数据或删除业务规则。

### 3.3 个人动作统计聚合

P0 定义统计的唯一计算口径，P1 只呈现结果，P2 不持久化统计快照。当前实现位于 `frontend/src/core/exerciseStats.ts`，由 `getExerciseDetail()` 读取本地 snapshot 后调用。

训练总量、重量换算和复合负载同样由 P0/core 的完整记录快照负载语义 helper 定义唯一口径。它接收动作的五项历史快照和组输入，统一输出输入重量 kg、重量倍率、计数倍率、聚合倍率、聚合次数/距离/时长、容量、距离负载、持续负载及速率所需分子/分母；调用方不得只传 `loadBasis` 后自行补倍率。`inputLoadKg = convertWeight(weight, unit, "kg")`；`loadMultiplier = loadBasis === "per_hand" ? 2 : 1`；`countMultiplier = countBasis === "per_side" ? 2 : 1`；`aggregateMultiplier = loadMultiplier * countMultiplier`。器械不得参与推断，页面、service、统计和分享不得手写倍率或拼接固定单位。

重量口径只说明重量输入：`total` 显示“重量”，`per_hand` 显示“每手重量”。计数口径独立说明次数、距离和时长输入：`whole_set` 按整组填写；`per_side` 表示一次填写的是每侧完成值，聚合时按两侧计入。它不记录左侧或右侧，也不允许左右重量、次数、距离、时长、PR 或休息时间分化。例如哑铃卧推 `20 kg/手 × 10 次、whole_set` 的容量为 `20 × 2 × 1 × 10 = 400 kg·次`；单臂哑铃划船 `20 kg × 每侧 10 次、per_side` 也是 `400 kg·次`；二者叠加时为 `800 kg·次`。农夫行走 `32 kg/手 × 40 m、whole_set` 的距离负载为 `2560 kg·m`。

| 模式/方向 | 派生口径 |
|---|---|
| `higher_better + weight_reps` | 容量 = 输入重量 kg × 聚合倍率 × 输入次数，单位 kg·次；总次数 = 输入次数 × 计数倍率。重量 PR 和 RM 均使用输入重量换算后的 kg，不乘任一倍率。 |
| `lower_better + weight_reps` | 辅助重量按 min/max 独立方向比较；不生成普通容量或 RM。 |
| `weight_duration` | 持续负载 = 输入重量 kg × 聚合倍率 × 输入时长，单位 kg·s；总时长 = 输入时长 × 计数倍率。 |
| `weight_distance_duration` | 距离负载 = 输入重量 kg × 聚合倍率 × 输入距离；只有时间时生成持续负载。总距离/时长分别按计数倍率聚合；三项齐全且启用竞速时，速率分子和分母使用一致口径，`per_side` 的倍率抵消。 |
| `distance_duration` | 聚合距离/时长按计数倍率计算；距离、时间齐全且启用竞速时分子和分母使用一致口径，`per_side` 不改变速度。 |

聚合输入是未 tombstone、`endTime != null` 的 WorkoutDoc。动作匹配沿用 P1 的替代解析：若历史 ID 被解析到当前详情动作，则计入该动作；原始历史 ID 和完整记录快照均不改写。`completedWorkoutCount` 按不同 WorkoutDoc 计数；`totalSetCount` 包含热身组，`workingSetCount` 与所有表现指标排除 `isWarmup=true` 的组。`recent7DaySetCount` 以今日为结束日，向前包含 7 个自然日，统计窗口内该动作的总组数。

每个指标必须按历史快照解释。成绩输入摘要保留 `loadBasis`、`countBasis`、原始重量及单位、次数、距离、时长和 RPE；聚合值、倍率和换算后的输入重量均由 helper 重算，不重复持久化。比较器为主值和每个 tie-breaker 分别声明 min/max，不能假定所有数值越大越好。换算使用固定常量 `1 lb = 0.45359237 kg`，只在展示层按统一规则舍入。不得以 `0` 的 falsy 判断替代 null 判断，不得把 kg·m 称为功或把 kg·m/s 称为功率。

当前调用链为：

```text
ExerciseDetailPage
  -> 现有动作详情 / 历史 service
  -> P0 纯统计聚合
  -> LocalJsonRepository 读取 ExerciseDoc 与 WorkoutDoc 月分片
  -> DocumentStore
```

空历史返回数值 0 与 `lastCompletedDate=null`，不是读取错误；读取失败由 service 向页面报告，不能以空统计掩盖。统计仅随本地训练增删改和同步后的本地合并重新计算，不创建远端查询或缓存索引。

## 4. 页面流程

### 4.1 训练创建：WorkoutCreatePage

路由：`/workouts/new`，可接受：

```text
/workouts/new
/workouts/new?date=YYYY-MM-DD
/workouts/new?template_id=<template-id>
```

进入页时先查询未结束草稿；有草稿时显示恢复对话，不进入新的 session state。选择“继续”会恢复同一训练 ID、已保存的动作/组、模板、日期、感受和备注；动作名称等展示元数据可取当前动作，但记录控件和再次保存必须继续使用草稿中的完整记录快照，不能用当前动作配置覆盖。选择“新建”会先通过 `completeWorkoutDraft` 结束旧草稿，再进入空白创建流程。

无草稿时状态机：

```text
select -> training -> rest -> training | select | finish
finish -> 保存后跳转 WorkoutDetailPage
```

关键步骤：

1. 首屏加载动作、启用计划和最后一个未结束草稿；若存在 `template_id`，加载模板并激活。
2. 激活模板后调用 `.filter()`，非模板动作不得渲染。页内选择器激活模板时必须得到相同行为。
3. 第一次选择动作时写入训练开始时间并启动总计时。
4. 完成一组时先更新内存 session，再立即调用 `createWorkout` 或 `updateWorkout`。
5. 休息结束、换动作或结束训练时，把 `restSeconds` 写回该动作最后完成的一组，再持久化。
6. finish 阶段保存 mood、note 和 `endTime`，跳转至详情页。

选择阶段的内联动作选择器不拥有纵向滚动区；具体动作列表随内容自然延展，从部位筛选下方的任一动作按钮开始上滑均由 P4 定义的 `app-main` 处理。模板编辑和训练编辑中的弹层动作选择器属于 P4 的模态例外，保留自身的列表滚动。

进入 finish 阶段时必须立即停止总计时，并用当时已显示的累计秒数固定 `endTime`；用户返回继续训练时才恢复计时。完成页和月列表按记录快照展示指标，只隐藏 `null`；不得用“0 kg”“0 m”“0 s”或 `0.0 kg·次` 代替未填写项。农夫行走三字段在 360px、412px 与横屏采用可换行布局，顺序为“每手重量、距离、用时”。

失败行为：本地写入异常必须通过 Toast 告知；不得静默丢弃已输入的 session state。未配置 WebDAV 不得阻塞任何步骤。

### 4.2 训练详情：WorkoutDetailPage

路由：`/workouts/:id`。

页面展示日期、模板 badge、动作、每组重量/次数/休息、总组数、容量、时长、备注和感受。菜单包含编辑、复制、分享、删除。

- 复制使用日期 bottom sheet；该弹层必须高于 Layout 的底部导航。
- 删除必须通过 ConfirmDialog 确认，再调用 `deleteWorkout`。
- 分享图由 P4.1 的 service/platform 链路本地生成；Android 保存进入系统相册，浏览器开发模式下载 PNG。分享图不进入训练文档或 WebDAV。

### 4.3 编辑：WorkoutEditPage

路由：`/workouts/:id/edit`。

编辑读取本地 WorkoutDoc 映射；保存时传入完整动作/组列表。新增组时 `setNumber = 当前组数 + 1`；删除组后必须重编号。编辑空字段时应以 `null` 表示显式清空，以 `undefined` 表示不改动。当前页面不提供 superset 编排控件，但必须把既有 `supersetGroup/superset_group` 从读取结果原样带回保存 payload。

### 4.4 列表、首页和日历入口

- WorkoutsPage 按 `month=YYYY-MM` 查询；总量和次数只基于该月有效训练。
- HomePage 的最近训练不按月限制，本月统计只查询该月。
- CalendarPage 只读取网格范围内实际训练记录，但月统计仅使用本月边界；计划/补训建议属于 HomePage 的 `getCalendar` 展示能力，不是当前 CalendarPage UI。
- 日历选中日期创建训练时传递 `date` 参数。

## 5. 复制、删除和时间边界

### 5.1 复制训练

复制语义是“复制训练内容，创建新的待完成训练记录”。

| 字段 | 复制规则 |
|---|---|
| `id`、嵌套动作/组 `id` | 必须新建。 |
| `date` | 使用调用者指定目标日期。 |
| `startTime`、`endTime` | 设为 `null`。 |
| `planTemplateId` | 保留。 |
| `note`、`mood`、sets 和 `restSeconds` | 保留。 |
| 元字段 | 由 repository 新建，不能沿用来源时间戳。 |

### 5.2 删除训练

删除不物理移除数组项，而是设置 `deletedAt`。因此：

- `listWorkouts`、动作历史、日历完成状态和统计必须忽略 tombstone。
- 同步仍会传递 tombstone，避免另一设备复活已删除记录。
- 未来真正清理 tombstone 前，需要同时考虑所有已同步设备，不在当前范围内。
- P5 的 AI 计划导入只能创建计划、模板和经确认的自定义动作；不得通过替代、批量更新或导入流程重写历史 Workout 的 exerciseId 或记录快照。

### 5.3 日期口径

`date` 是训练归属日期，不从 ISO 开始时间推导。月统计使用 `monthStart <= date <= monthEnd`；日历加载范围可扩展到周网格，但不应扩大月统计范围。
