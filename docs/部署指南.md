# IronLog 发布与交付指南

> 适用版本：Android-first 本地单人版
> 当前目标：通过 GitHub Releases 发布应用名为“IronLog录铁”的 Android 内部测试 APK；也可交付静态 Web 构建产物。不使用 Google Play，不部署 FastAPI、PostgreSQL、Docker、Nginx 或服务器。
> 发布状态：尚未发布首个内部测试版；当前测试候选不构成数据兼容基线。

---

## 1. 发布模型

IronLog 当前有两种交付形态：

| 形态 | 产物 | 适用场景 | 数据位置 |
|---|---|---|---|
| Android APK | `app-debug.apk` 或签名 release APK | 日常单人使用、WebDAV 原生同步 | Capacitor Filesystem |
| 静态 Web | `frontend/dist/` | 开发预览、功能演示 | 浏览器 IndexedDB |

静态 Web 不等同在线 SaaS：它没有业务后端，也不能替代 Android 对 WebDAV 非标准方法的原生支持。对外主交付应以 Android APK 为准。

## 2. 发布前检查

```powershell
cd D:\workspaces\vscodeWorkspace\project\bodybuilding\ironlog\frontend
npm ci
npm run build
npm test
npm run test:layout
npm run android:sync
```

还应人工走查：

- 无 WebDAV 配置时可创建、编辑、复制和删除训练。
- 模板训练的 URL 入口和页内选择器都能真正过滤动作。
- WebDAV 测试连接、手动同步和冲突日志可显示。
- Android 真机可访问 HTTPS WebDAV 服务。
- `settings.json` 远端副本不含密码引用与最后同步时间。
- 精选动作目录实施后，新安装动作集合与 `candidates.md` 一致，分类无 `compound`，记录类型唯一，器械与分段说明可读，来源信息不在前端展示。
- 使用空的隔离 WebDAV 目录完成首次上传；远端 JSON 和构建产物不含 Media、媒体 URL、`media_id` 或非中文 instructions。

在发布说明中必须明确当前限制：LWW 冲突策略、无自动备份清理、Web 开发 secret 安全等级低于 Android、没有用户可操作的导入/导出 UI。

## 3. 构建 Android APK

### 3.1 开发版 APK

```powershell
cd D:\workspaces\vscodeWorkspace\project\bodybuilding\ironlog\frontend
npm run android:sync

cd android
.\gradlew.bat assembleDebug
```

输出通常在：

```text
android/app/build/outputs/apk/debug/app-debug.apk
```

debug APK 仅用于本机调试，不作为 GitHub Release 资产。

### 3.2 GitHub Releases 使用的签名 release APK

当前仓库未固化 release 签名密钥。首次向 GitHub Releases 分发时，在 Android Studio 中执行：

1. 打开 `frontend/android`。
2. 选择 **Build -> Generate Signed Bundle / APK**，并选择 APK，不选择 Android App Bundle。
3. 创建或选择长期稳定的 keystore，生成 release APK。
4. 将 keystore 和密码保存在仓库外的受控位置。
5. 不提交 keystore、密钥密码或 `key.properties` 到 Git。

同一 `applicationId` 的后续 APK 必须继续使用同一签名密钥，否则 Android 无法覆盖升级。若需要 GitHub Actions 自动发布，再新增不含密钥的签名配置模板和 GitHub Actions Secrets 说明；在此之前不要把 keystore 或密码写入仓库或工作流文件。

### 3.3 安装与验证

```powershell
adb install -r IronLog-0.1.0-internal.2-android.apk
```

或将 APK 传到设备后手动安装。首次安装后，至少完成一次离线训练和一次 WebDAV 同步测试。

精选动作目录构建属于兼容基线前的开发期数据替换，不把 `adb install -r` 后旧测试数据仍可读取作为验收条件。构建读到旧 schema 快照时必须以明确错误停止，不迁移、不静默丢弃，也不得自动清空应用或远端数据。应在全新 AVD 或定向清理后的测试 AVD 上验证；不得要求在日常真机清空应用数据、Keystore 或远端目录。

### 3.4 GitHub Release 资产与标签

内部测试 Release 使用 Git tag `v0.1.0-internal.2`，并标记为 pre-release。至少上传：

- `IronLog-0.1.0-internal.2-android.apk`：稳定密钥签名的 release APK。
- `SHA256SUMS.txt`：APK 的 SHA-256 校验值。

Release notes 应包含版本号、主要修复、安装方法、最低 Android 版本、WebDAV 限制和本地数据提醒。首个内部测试兼容基线建立前的精选动作目录构建必须明确“旧开发测试数据不兼容，需新建测试快照”，不能宣传覆盖升级保留；兼容基线建立后才提供升级迁移与回滚说明。GitHub 会按 tag 自动附带源码 zip/tar.gz，不必重复上传源码压缩包。发布新构建后，旧 tag 和旧 Release 资产不得原地替换；必须递增 `buildNumber`、`versionCode` 和内部版本后创建新 tag。

Android 设备从 GitHub 下载 APK 时需要允许浏览器或文件管理器“安装未知应用”。面向更广用户分发前，还应根据 Android Developer Verification 的当前规则，在 Android Developer Console 注册开发者身份、包名 `app.ironlog.local` 与 release 签名密钥；该注册不要求把应用上架 Google Play。小范围个人测试可根据届时规则选择有限分发或由高级用户启用侧载流程。

## 4. 静态 Web 预览

```powershell
cd D:\workspaces\vscodeWorkspace\project\bodybuilding\ironlog\frontend
npm run build
npm run preview
```

`dist/` 可以部署到任意静态托管。静态站点不需要 API 反向代理、数据库环境变量或服务器密钥。若在浏览器中配置 WebDAV，服务器仍需正确允许相应 CORS/HTTP 方法；因此不能把 Web 预览当成 Android 同步兼容性的验证替代品。

## 5. 数据与版本兼容性

### 5.1 本地数据

本地数据在 `ironlog-data/` 逻辑目录中按 JSON 分片保存。当前尚未建立内部测试兼容基线且没有真实用户数据；经批准的默认动作和非关键字段变更直接替换开发测试快照。兼容基线建立后，升级应用前若数据重要应先完成一次成功的 WebDAV 同步。卸载应用、清除应用数据、清除浏览器站点数据都会删除本地副本。

### 5.2 schemaVersion

兼容基线建立后，每次新增或变更持久化字段时，发布说明必须记录数据兼容性、迁移和回滚限制，并完成相应验证。当前精选动作目录实施只递增当前 schema、重建测试快照，不提供旧测试 schema/default migration；具体规则见 P1、P2 和《默认动作库引入实施方案》。

### 5.3 WebDAV 备份

每次同步前，应用会把远端已有分片复制到 `backups/`。该行为是同步失败时的恢复线索，不是完整的用户级备份/恢复产品；发布前不要承诺“一键恢复”能力。

主题、动作库 Tab 与动作详情已进入当前发布能力；当前候选已按 P4 完成 360px、412px、横屏自动布局测试和 Android 16（API 36）AVD 的 411px、5 套主题视觉验收。AI 仍为规划能力，不能写入当前发布说明；未来 AI 未配置或调用失败时，现有离线能力必须保持可用。

### 5.4 内部测试版发布元数据方案

当前修复候选已由 `frontend/release/version.json` 单一权威文件定义：基础版本 `0.1.0`、渠道 `internal`、内部构建序号 `2`、Android `versionCode 2`，生成的 Android `versionName` 为 `0.1.0-internal.2`。本轮需要与真机发现问题前的候选包明确区分，因此不复用 `versionCode 1`。产品展示名为“IronLog录铁”，`applicationId` 继续为 `app.ironlog.local`，不会触发本地数据目录迁移。

`package.json` 仅保存基础版本，必须与权威文件的 `baseVersion` 相同。`android/version.properties` 由 `npm run release:sync` 生成并受版本控制；`android/app/build.gradle` 只读取该文件，禁止手工维护 `versionName` 或 `versionCode`。`npm run build` 的预检查会运行 `npm run release:check`，在 `package.json`、权威文件和 Android 属性文件任一不一致时失败。Android 同步会先执行 `npm run release:sync`。

准备下一次内部包时，修改 `release/version.json`：递增 `buildNumber` 和 `android.versionCode`，并把新的 `versionCode` 追加到严格递增的 `issuedVersionCodes` 账本；随后运行：

```powershell
cd D:\workspaces\vscodeWorkspace\project\bodybuilding\ironlog\frontend
npm run release:sync
npm run release:check
npm run android:sync
```

账本只能防止仓库中已记录的版本号复用或倒退；发布者仍须在分发前核对测试渠道/应用商店中已上传的最高 `versionCode`，并将其补入账本后再递增。升级到正式 `1.0.0` 时，将 `baseVersion` 与 `package.json` 同步改为 `1.0.0`，设置合适的正式渠道标识，且 `versionCode` 必须继续大于所有已记录值，绝不能从 `1` 重计。发布说明还应记录上一版本、数据兼容性和最低兼容版本。

旧 `0.1.0-internal.2` 测试候选曾在 Android 16（API 36）AVD 使用 `adb install -r` 核对同一 APK 覆盖安装；该结果不适用于尚未实施的精选动作目录构建，也不构成对外数据兼容承诺。新目录构建须按本指南重新建立干净测试快照并重新验收。

### 5.5 WebDAV 密码的 Android Keystore 存储（已实现）

当前实现使用项目自有的最小原生 `SecretStore` 适配器：

1. platform 层提供 `readSecret`、`writeSecret`、`removeSecret`；页面、service、repository 和同步层不依赖 Keystore 或 Preferences 细节。
2. Android Keystore 保存不可导出的 AES-256 密钥，密码使用 AES-GCM 认证加密；每次写入生成新 IV。带独立格式版本的密文、IV 保存在应用私有 SharedPreferences 文件中，secret ref 经 SHA-256 映射为存储键。
3. 首次读取若新存储不存在但旧 Preferences 值存在，按“写新、读回确认、删旧”迁移；新存储未确认前保留旧值。旧值删除失败不影响使用已确认的新值，后续读取继续清理。
4. 密文损坏或 Keystore 密钥不可用时提示重新输入密码；重新输入可覆盖损坏记录。清除同步配置同时清理新存储和旧 Preferences，失败时保留端点并提示重试。
5. Web 开发环境仍使用 IndexedDB 独立 secret 键，只适合本地开发，不具备 Android Keystore 的安全等级。

密码正文、密文、Keystore alias 和解密材料不进入 `settings.json`、manifest、WebDAV 分片、backup 或日志。该实现不承诺密钥由硬件安全模块保护，也不构成端到端加密；卸载、清除应用数据、换机或系统凭据变化后不保证恢复。当前代码未强制拒绝 HTTP URL，内部测试必须使用 HTTPS，对外配置应强烈建议 HTTPS 和权限受限的专用账户。

TypeScript 迁移/调用边界测试、Android JVM 测试、debug APK 和 instrumentation test APK 可在本机构建。Instrumentation 只运行 `:app:assembleDebugAndroidTest` / `:app:connectedDebugAndroidTest`；项目级 `assembleDebugAndroidTest` 的 Capacitor Cordova 插件模块 Kotlin 重复类问题不影响主 APK。当前候选已在 Android 16（API 36）AVD 完成 4 项 instrumentation、系统返回键与边缘返回手势、相册 PNG 落盘、重启和覆盖安装数据保留验证，并在目标真机通过 HTTPS WebDAV 保存、读取、重启后同步及远端脱敏检查。

训练详情的“保存图片”在 Android 通过原生 `ImageSaver` 写入系统相册 `Pictures/IronLog`；Android 9 及以下需要旧版存储权限，Android 10 及以上使用 MediaStore。该测试只新增 PNG，清理时只删除测试图片，不得清除应用数据、Keystore 或 WebDAV 目录。
