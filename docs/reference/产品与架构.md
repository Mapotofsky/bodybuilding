# 产品与架构

本文定义 IronLog 当前产品范围和跨领域边界。任务入口与各领域的唯一规则位置见[文档入口](../README.md)；长期选型理由见[本地优先架构决策](../decisions/2026-06-本地优先架构.md)。

## 产品范围

IronLog 是开源、Android-first、本地优先的单人训练日志应用。用户可离线完成训练记录、计划与模板编排、动作库浏览、日历与统计、身体数据和成绩查看；WebDAV 是可选的手动 JSON 同步与备份。应用不需要账号、业务服务器或数据库服务。

当前范围不包括登录、多人共享、服务端 API、社区、Wiki、管理后台、自动后台同步、端到端加密、可视化冲突解决或用户可操作的数据导入/导出界面。AI provider/API key、问答、联网检索及候选计划导入尚未实现；已讨论的边界和待决事项见[未实现：可选 AI 能力](../proposals/可选AI能力.md)。旧 FastAPI/PostgreSQL 路线不属于当前运行依赖。

## 运行与代码边界

```text
React pages -> services -> repositories -> DocumentStore
                                      -> Web: IndexedDB
                                      -> Android: Capacitor Filesystem

可选同步：repository -> SyncService -> WebDavClient -> WebDAV
```

页面和业务 service 不判断实际存储来源，也不直接访问平台存储。`src/core` 保持纯 TypeScript，不依赖 React、DOM、Capacitor、WebDAV 或具体存储实现。Repository 隔离 IndexedDB、Capacitor Filesystem、WebDAV 及未来适配器；Android 原生功能由 platform 与 sync 层封装。未来平台扩展不得改变本地真源和离线可用性；新增业务服务或云适配须先重新确定数据所有权与同步语义。

业务数据以本机 `DataSnapshot` 为真源，按 JSON 文档分片持久化；WebDAV 不承担实时数据库职责。训练按月分片，`WorkoutDoc` 保留聚合文档形态，不能回退成需要 SQL join 的分表模型。可持久化文档使用稳定 string ID、创建和更新时间、删除标记与业务 schema；删除、替代及迁移须保存既有历史事实。完整字段、分片布局、兼容范围和迁移规则由[本地存储与迁移](本地存储与迁移.md)定义。

## 跨领域不变量

- 训练时的记录方式与口径须随训练记录保存快照；动作后续修改、删除或替代不能重解释历史。记录方式注册表、重量及计数语义以[核心训练](核心训练.md)和[计划与动作库](计划与动作库.md)为准。统计、成绩、分享与页面使用 core/service 的同一解释。
- 已有本地和 WebDAV 快照都按可能含用户数据处理。字段、默认目录和迁移变更不能以清空、整体覆盖或断开引用代替兼容处理；数据演进的具体规则见[本地存储与迁移](本地存储与迁移.md)。
- WebDAV URL、用户名、`passwordRef`、密码及其他本机秘密配置不能进入 `settings.json`、manifest、同步分片、远端备份或日志。远端合并保留本机配置；同步与 Android 凭据的具体契约分别见[WebDAV 同步](WebDAV同步.md)和[Android 平台与凭据](Android平台与凭据.md)。
- 无网络或未配置 WebDAV 时，训练、计划、模板和动作库仍可使用。AI 等可选外部能力失败时也不得破坏本地训练数据。
- 用户可见的统计、单位换算和领域语义须来自单一 core/service 实现；页面不另建并行解释。用户文案围绕任务表达，不暴露 schema、payload 或内部验收语言。
