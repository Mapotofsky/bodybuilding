# 本地文档存储与数据迁移

> 本文是业务 schema、分片、DocumentStore 和兼容 migration 的当前权威。领域语义见对应参考文档；远端合并见[WebDAV 同步](WebDAV同步.md)。

---

## 1. 设计目标与边界

本模块在无服务端环境中提供训练、动作、计划、模板、资料和设置的本地真源。它解决三个问题：

1. 同一业务代码在浏览器开发和 Android 上可读写相同 JSON 逻辑文件。
2. JSON 以静态文件与训练月分片保存，不退化为单一巨型文件。
3. 文档格式变化可通过 schemaVersion 归一化，而不是要求页面兼容所有旧字段。

本模块不负责：WebDAV 网络 IO、同步冲突合并、用户可操作的导入/导出 UI、Android Keystore 加密细节。它提供 `DocumentStore`、`SecretStore` 和 `LocalJsonRepository` 的平台边界；Android 加密与凭据迁移流程见[Android 平台与凭据](Android平台与凭据.md)。

## 2. 文件、快照和 manifest

### 2.1 逻辑文件

| 路径 | 内容 | 更新来源 |
|---|---|---|
| `manifest.json` | 应用标识、schema、设备 ID、分片列表 | 任意 repository mutation 后重建。 |
| `profile.json` | ProfileDoc | 更新本地资料。 |
| `settings.json` | SettingsDoc | 更新可同步偏好，不保存 WebDAV 端点配置。 |
| `exercises.json` | ExerciseDoc[] | 内置/自定义动作、tombstone 与替代重定向。 |
| `templates.json` | `{ plans, templates }` | 计划、模板变更。 |
| `body-metrics.json` | BodyMetricDoc[] | 身体数据与备注 身体指标稀疏测量记录，已实现。 |
| `timeline-notes.json` | TimelineNoteDoc[] | 身体数据与备注 日期/时间段背景备注，已实现。 |
| `workouts/YYYY-MM.json` | WorkoutDoc[] | 该月训练创建、编辑、删除、复制。 |
| `exercise-performance/YYYY-MM.json` | ExercisePerformanceRecordDoc[] | RM 与动作成绩 动作成绩刷新事件，已实现。 |
| `assets/avatar/*` | 头像资源文件 | ProfilePage 选择、替换或清除头像。 |

`DataSnapshot.workouts` 是运行时聚合数组。训练的磁盘真源只允许是月分片；不得新增全量 `workouts.json` 或另一份训练索引文件。

### 2.2 IronLogManifest

```ts
interface IronLogManifest {
  app: "ironlog";
  schemaVersion: number;
  deviceId: string;
  updatedAt: string;
  shards: Array<{
    path: string;
    updatedAt: string;
    etag?: string | null;
  }>;
}
```

`buildShardList(snapshot)` 输出六个静态分片、实际存在的训练月分片、动作成绩月分片以及头像资源文件。某月只有 tombstone 训练或成绩事件时，该分片仍必须列出并同步；否则另一设备可能恢复已删除记录。

### 2.3 分片规则

```ts
workoutShardPath("2026-06-22") === "workouts/2026-06.json"
isWorkoutShardPath(path) === /^workouts\/\d{4}-\d{2}\.json$/
```

日期不合法不能用于构造分片路径。当前 service 依赖页面传入 `YYYY-MM-DD`；后续若开放导入，导入层必须在写入前校验日期。

## 3. DocumentStore 平台接口

定义位置：`frontend/src/platform/documentStore.ts`。

```ts
interface SecretStore {
  readSecret(key: string): Promise<string | null>;
  writeSecret(key: string, value: string): Promise<void>;
  removeSecret(key: string): Promise<void>;
}

interface DocumentStore extends SecretStore {
  load(): Promise<Partial<DataSnapshot> | null>;
  save(snapshot: DataSnapshot): Promise<void>;
  readSyncEndpoint(): Promise<SyncEndpointConfig>;
  writeSyncEndpoint(config: SyncEndpointConfig): Promise<void>;
  clearSyncEndpoint(): Promise<void>;
  exportFiles(snapshot: DataSnapshot): Record<string, unknown>;
  importFiles(files: Record<string, unknown>): Partial<DataSnapshot>;
}
```

### 3.1 浏览器实现：IndexedDbDocumentStore

- 使用一个 IndexedDB object store 保存逻辑路径到 JSON 对象的映射。
- manifest 是读取入口；先读 manifest，再读静态文件和其中列出的训练分片。
- 浏览器 secret 当前也保存在 IndexedDB 的独立 key 前缀下，只用于开发兼容，不代表安全凭据库。
- 清理站点数据或隐私模式结束会删除这些数据。

### 3.2 Android 实现：CapacitorDocumentStore

- 使用 Capacitor Filesystem `Directory.Data` 下的 `ironlog-data/`。
- 保存时先写所有非 manifest 分片，再写 manifest，最后删除旧 manifest 中已不存在的训练月分片。
- 只有 Capacitor Filesystem 明确返回“不存在”错误码时读取才返回 `null`，供旧版本缺少静态分片时由 migration 补齐；权限、I/O 等其他读取错误必须携带逻辑路径显式阻断。文件存在但 JSON 无法解析时同样阻断，不得伪装成缺失。manifest 已引用的训练、成绩或资源分片若缺失，IndexedDB 与 Capacitor Filesystem 都必须阻断加载和后续写回，避免把无法读取的记录当作空集合删除。
- Preferences 保存 URL、用户名和 `passwordRef` 等本机端点配置，并只作为旧版密码迁移源。新密码通过 Android `SecretStore` 写入 Keystore 保护的加密存储；密码、密文和解密材料均不进入 DocumentStore JSON。

### 3.3 平台选择

`createDocumentStore()` 仅在 `window.Capacitor.isNativePlatform()` 为真时选择 Capacitor 实现，否则选 IndexedDB。SecretStore 同样由 platform 层选择：Android 为 Keystore 加密实现，Web 为 IndexedDB 开发实现。业务模块不得自行分支判断平台。

---

### 3.4 设置与本机端点

当前 SettingsDoc 包含 weightUnit、themeId、lastSyncAt。WebDAV url、username、passwordRef 是本机-only 同步端点配置，通过 DocumentStore 本地配置接口保存；password 明文只能通过 DocumentStore secret 保存。它们不得进入 `settings.json`、manifest、远端 JSON 分片或 backup。themeId 使用稳定 string ID，默认 emerald-slate；未知值由 UI 回退但 migration 和同步不得改写原值。AI 设置尚未实现，候选方案见[未实现：可选 AI 能力](../proposals/可选AI能力.md)。

`0.1.0-internal.2` 已建立内部测试兼容基线。新增持久化字段必须递增 schemaVersion，添加显式 migration、读取后写回、DocumentStore export/import 与 WebDAV 往返测试；不得假定已有快照为空，也不得用清空或覆盖代替升级。

### 3.5 动作详情元数据

`ExerciseDoc` 的完整领域字段、受控记录方式、重量口径、计数口径、成绩方向、竞速指标、器械、分段 description、肌群和 provenance 由[计划与动作库](计划与动作库.md)定义。本节只定义存储接入，不把上游 `category/body_part/target/muscle_group` 当作存储模型。

本节只定义持久化边界：`DataSnapshot.exercises` 整体写入 `exercises.json`；IndexedDB、Capacitor Filesystem、DocumentStore export/import 与 WebDAV 必须原样保存所有 `ExerciseDoc` 字段。`description` 仍是一个 `string | null`，内部换行原样往返；不增加平行的步骤字段。`provenance` 位于同一文档内但不经过页面 DTO，不能因为 UI 未展示而在 mapper、repository 更新或同步往返中丢失。Media 字段和非中文 instructions 不进入 `DataSnapshot` 或构建产物。

v5 是 `0.1.0-internal.2` 的兼容基线。v6 曾在开发构建中把爬楼机保存为 `recordingMode=step_count_duration`、`rateMetric=steps_per_time`，部分或全部动作/训练快照缺少 `contextKind`；不能因为 manifest 已标 v6 就跳过迁移。v7 将这两个旧枚举显式映射为 `reps_duration/reps_per_time`，缺失上下文补 `none`，并继续兼容 v5 的 `contextKind/contextValue` 补齐。v8 把默认目录从 63 条增量扩展到 87 条，新增 `trap_bar` 器械枚举，并以稳定 ID 更新内置动作的分段 description 和受控目录字段；19 条新增动作保存固定上游 provenance，5 条自编动作显式省略 provenance。兼容读取仍按以下条件处理旧内置说明，不另升 schema：仅当同 ID 的内置动作 `description` 含 `\n\n` 时，以当前 `DEFAULT_EXERCISES` 的 description 定向替换；自定义动作不参与，其他字段、tombstone、未知记录和 WorkoutDoc 历史不改写。该融合在每次读取后写回，替换完成后条件不再成立，因而幂等。历史训练不按当前目录重解释；自定义动作、未知动作、嵌套 ID、未展示字段和 tombstone 保留。阻力动作的旧派生成绩写 tombstone，WorkoutDoc 原始事实不删除。

生成目录采用确定性两段式：`candidates.md` 保存生成所需的完整 IronLog 映射，并为有来源动作保存固定上游 ID；自编动作以 `-` 明确表示无可核验同义来源，生成时省略 provenance。内容评价、上游 `instruction_steps.zh`、人工纠错和未来交接规则保存在版本化内容候选文档。生成文件只输出不含 BaseDoc 元字段的 `DefaultExerciseSeed[]`，六项记录配置逐条来自映射，不得按器械或名称推断；`defaultData.ts` 使用固定 seedTime 补齐元字段。

### 3.6 头像资源

`ProfileDoc.avatarUrl` 保存头像资源路径引用，例如 `assets/avatar/profile-local.txt`，不保存 base64 正文。头像正文由 DocumentStore 作为资源文件保存；Web 端和 Android 端均通过同一 service 读取为 data URL 预览。ProfilePage 选择或替换头像时先写入资源文件，再把 profile 引用改为该路径；清除头像时将 `avatarUrl` 置为 null 并删除旧资源。

头像资源必须进入 manifest shards，并随[WebDAV 同步](WebDAV同步.md)定义的 tmp/MOVE 流程发布。远端已有头像资源在覆盖前写入 `backups/`；清除头像后，下一次同步根据新 manifest 删除远端过期头像资源。profile 与资源文件的边界是：profile 只保存引用，资源正文不进入 `profile.json`、`settings.json` 或训练分片。当前工程先实现 Web 文件选择和本地资源接口；若 Android WebView 的文件选择能力受设备限制，后续再增加 Capacitor 原生选择器适配。

### 3.7 未实现的批量导入依赖

当前 createPlan、createTemplate、createExercise 是独立 mutation，尚无批准计划批量提交原语。若实现[可选 AI 候选导入](../proposals/可选AI能力.md)，须先定义在 snapshot 副本上应用已验证变更、一次保存、成功后替换正式 snapshot、失败保留正式 snapshot 的原子提交契约；候选校验、未知动作决议和预览属于该未实现方案。

### 3.8 分片与跨层接入

新增或改变持久化字段时，先在所属领域参考文档确定语义，再确认分片、migration、DocumentStore 和远端往返的接入位置；字段全集与页面展示规则不在这里复制。

| 文档或资源 | 本地与远端位置 | 存储接入要点 | 领域规则 |
|---|---|---|---|
| `ExerciseDoc` | `exercises.json` | 默认目录按稳定 ID 融合；自定义、未知、tombstone、provenance 和未展示字段须保留 | [计划与动作库](计划与动作库.md) |
| `TrainingPlanDoc` 与 `TemplateDoc` | `templates.json` | 计划、模板及稳定嵌套动作 ID 原样保留；更新不得重建未改变的引用 | [计划与动作库](计划与动作库.md) |
| `WorkoutDoc` | `workouts/YYYY-MM.json` | 聚合、嵌套 ID 和训练时六项记录快照原样保留；历史不按现行动作重解释 | [核心训练](核心训练.md) |
| `BodyMetricDoc` | `body-metrics.json` | 新快照初始化空数组；旧 Profile 身高体重不推断为新测量事实 | [身体数据与备注](身体数据与备注.md) |
| `TimelineNoteDoc` | `timeline-notes.json` | 新快照初始化空数组，保留训练引用与删除标记 | [身体数据与备注](身体数据与备注.md) |
| `ExercisePerformanceRecordDoc` | `exercise-performance/YYYY-MM.json` | 按达成时间分片，保留来源训练、动作和组 ID；旧派生成绩依 migration 处理 | [RM 与动作成绩](RM与动作成绩.md) |
| `ProfileDoc` 与头像资源 | `profile.json`、`assets/avatar/*` | profile 仅保存资源引用；资源列入 manifest 并参加备份和发布 | [WebDAV 同步](WebDAV同步.md) |
| `SettingsDoc` | `settings.json` | 可同步偏好进入分片；WebDAV 端点、secret 和本机时间戳不得进入远端 | [WebDAV 同步](WebDAV同步.md)、[Android 平台与凭据](Android平台与凭据.md) |
| 分享图 PNG | 不进入 DataSnapshot 或 manifest | 本地输出物，不随业务分片同步 | [日历与统计界面](日历与统计界面.md) |

每个受影响字段都应沿页面输入或读取、service、core 文档、mapper、repository、migration、DocumentStore、JSON 分片和 WebDAV 往返追踪。只有实际受影响的层需要更新与验证；当前 schema 的迁移细节见第 5 节。

## 4. LocalJsonRepository

文件：`frontend/src/repositories/localJsonRepository.ts`。

### 4.1 初始化

```text
getSnapshot()
  -> DocumentStore.load()
  -> makeEmptySnapshot(deviceId)（空存储时）
  -> migrateSnapshot(raw, deviceId)
  -> DocumentStore.save(snapshot)
```

设备 ID 用 `localStorage` 中的 `ironlog_device_id` 保存；在 Android WebView 中它仅用于 manifest 标识，不是账户标识。

### 4.2 CRUD 规则

| 操作 | Repository 行为 |
|---|---|
| create | `withDoc` 生成 string ID、createdAt、updatedAt、deletedAt=null、schemaVersion=`CURRENT_SCHEMA_VERSION`。 |
| update | `withoutUndefined` 后合并；`undefined` 不覆盖旧字段；更新 `updatedAt`。 |
| delete | `tombstone` 写 `deletedAt` 和 `updatedAt`。 |
| list/get | 默认过滤 tombstone；需要历史/同步时显式 `includeDeleted`。 |
| mutate | 更新 manifest.updatedAt，重建 manifest.shards，调用 DocumentStore.save。 |

训练创建/更新还有额外规则：若嵌套动作或组 ID 为 `""`，repository 生成新 ID。复制训练必须显式把来源嵌套 ID 置空，不能只复制数组引用。

### 4.3 原子性限制

当前 repository 是内存快照 + 全量相关分片写入模型；它没有跨文件事务或本地临时文件发布。一次写入中断时可能留下部分新分片和旧 manifest。当前恢复策略是以 manifest 为读取入口；后续要提高可靠性时，应引入本地临时文件、校验和或写入日志，而不是在页面中补偿。

## 5. schema migration

文件：`frontend/src/core/migrations.ts`。

### 5.1 当前行为

`CURRENT_SCHEMA_VERSION = 9`。存储不存在时创建完整 v9 快照；读取 v5、v6、v7 或 v8 时执行显式增量迁移，读取 v9 时严格归一化并原样保留。v8→v9 将既有训练的 `restStartedAt` 补为 null，不根据 `updatedAt` 猜测休息起点，也不改写原有组记录。v4 及更早或未来版本明确拒绝，不转换、不清空。JSON 损坏或 manifest 引用分片缺失时也明确拒绝，并且不得进入 migration 写回。

v5/v6→v7 同时处理静态动作、WorkoutDoc 月分片和成绩月分片：v6 旧爬楼机枚举映射为当前枚举，缺失 `contextKind` 补 `none`；v5 组补 `contextValue=null`，v6 已有组上下文值不覆盖；旧阻力成绩 tombstone。v7→v8 只扩展受控器械枚举并按稳定 ID 融合 87 条当前内置目录；新增 24 条稳定 ID，更新旧 63 条 description，保留已有内置 tombstone、`createdAt`、`replacedByExerciseId`、自定义/未知动作、未展示字段和全部 WorkoutDoc 历史快照。迁移后重建 manifest.shards，并经 DocumentStore 与 WebDAV 使用同一路径。

### 5.2 开发期动作目录替换与兼容基线后的迁移

v5 基线之后不再使用开发期整体替换。目录融合只覆盖稳定内置 ID 的受控内容字段，不删除本地额外记录；WorkoutDoc 永远是训练事实真源。只有用户明确指定的浏览器测试数据、Android 虚拟机和隔离 WebDAV 测试目录可以人工清理。

兼容基线建立后，每次增加 `schemaVersion` 都必须：

1. 在 `models.ts` 定义新字段和默认/空值语义。
2. 新增从当时当前版本到下一版本的显式 migration 分支，例如当前后续变更应为 `v9 -> v10`，不能仅靠对象展开。
3. 同时迁移静态文件和 workout 月分片。
4. 保留 tombstone 与未知字段的兼容策略。
5. 添加旧快照升级测试、无数据初始化测试和同步后加载测试。
6. 更新 manifest schemaVersion，并在发布说明描述不可逆风险。

测试必须覆盖非空 v5 快照升级、AVD 实际 v6 旧枚举升级、非空 v7 快照到 87 条目录的增量融合、v8 草稿到 v9 的休息边界迁移、自定义/未知动作保留、内置 tombstone 保留、未结束草稿恢复、WorkoutDoc 与嵌套 ID 保留、阻力旧成绩 tombstone、迁移写回后稳定读取、JSON/WebDAV 往返、JSON 损坏与 manifest 引用分片缺失阻断、v9 幂等读取以及 v4/未来版本拒绝。应用本身不得执行清空。

当前以[身体数据与备注](身体数据与备注.md)中的 `BodyMetricDoc` 替换旧 `ProfileDoc.height` / `ProfileDoc.weight`。v5/v6 兼容读取会移除这两个旧 Profile 字段，但不会把旧单值推断为新的身体测量事实；其余 Profile 字段和已有 `BodyMetricDoc` 原样保留。该行为属于显式 migration，不能通过清空快照替代。

### 5.3 导入/导出边界

DocumentStore 已提供 `exportFiles` / `importFiles` 辅助函数，用于把 snapshot 转为逻辑文件集合或反向解析。当前没有用户 UI、文件选择器、完整格式校验或覆盖确认流程；不得在文档中宣称“已提供数据导入导出”。

后续导入流程至少要：校验 manifest、校验路径白名单、执行 migration、显示将覆盖/合并的文档数量、创建本地备份，再调用 `replaceSnapshot`。

人工验收：

- Web 开发刷新后训练仍可读取。
- 训练写入正确月分片，不生成全量 `workouts.json`。
- 删除训练后常规列表隐藏、分片保留 tombstone。
- 更新设置不把 `undefined` 写成字段值。
