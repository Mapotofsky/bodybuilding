# IronLog 文档治理

## 权威职责

先按 [文档入口](../../../docs/README.md) 找到本次任务所属的当前参考文档，再只读取受影响引用文档。[产品与架构](../../../docs/reference/产品与架构.md)定义产品范围和跨领域不变量；领域参考文档各自定义完整规则。[开发与验证](../../../docs/guides/开发与验证.md)和[发布与升级](../../../docs/guides/发布与升级.md)只保存读者实际执行所需的步骤。

## 内容去向

在会话内判断每项改动属于当前事实或限制、未来规划、方法或规则，据此选择事实源和权威位置。分类只服务于执行判断，不是交付文档的模板。参考文档和指南直接呈现读者需要的当前状态及操作，不写入分类标签、任务提示、Skill、核验或治理过程。

当前事实和限制以与本次改动直接相关的代码、配置、脚本、版本元数据或 migration 为准；规划清楚表达未实现状态；完整方法或规则只保留在负责回答该问题的一个权威文档。只有另一篇文档的目标读者的操作或判断会变化时，才修改其正文；否则仅修复必要链接。代码与配置可直接查得的版本、命令和字段清单不在多篇正文中缓存。

一次性任务执行计划留在任务中；已确定但未实现的产品方案进入 `docs/proposals/`，长期有效的取舍进入[决策记录](../../../docs/decisions/2026-06-本地优先架构.md)，当前有效的规则进入参考文档。阶段需求、旧验收和诊断证据可保留在 `docs/history/`，并标明形成时间；有证据的后续修复可按日期补记提交、处理结果、验证范围和未解问题，其中旧的“当前实现”不能充当现行规范。数据兼容基线由[本地存储与迁移](../../../docs/reference/本地存储与迁移.md)定义，发布状态只在发布操作语境中陈述。

## 修改工作流

1. 在会话内确定每项事实、规则和状态的唯一权威位置，不创建治理台账。
2. 修改产品与架构边界时检查受影响领域是否仍符合边界；修改领域参考文档时检查是否越权定义其他领域。
3. 同一概念需要修改多份文档时，逐份确认独立读者职责；搜索只用于定位直接矛盾、重复权威和受影响引用，每个命中按所在文档的读者职责处理。
4. 文档职责变化、合并、拆分或归档时，搜索旧职责下的相关段落和链接，处理整个职责而不是只改标题或状态。
5. 删除或迁移仍影响当前决定的内容时，以当前行为证据、接收位置、仍有效的更一般规则或明确废止依据支撑改动；无法可靠判断时保留该项并报告。只承载已失去当前价值的历史叙事可以直接删除。
6. 保留文档履行权威职责所需的指标、算法、决策依据和验收方法；文档整理不自行改变产品或工程语义。无需每次变更都写 ADR 或同步更新所有相关文档。高风险变更在实现前明确兼容、失败和验收条件，完成后按实际影响更新当前契约与操作指南。

## 验收

- 只核对本次新增、删除、改写或作为判断依据的事实，并按事实类型选择直接证据；不把每次修改扩展为代码路径、命令、版本、schema、applicationId、路由和状态的全量盘点。
- 逐份抽查修改后的中文、标题层级、相对链接和读者语境；审查搜索命中的直接矛盾、重复权威和受影响引用。
- 执行 Skill 或仓库已有的结构检查、审查完整 diff 并运行 `git diff --check`；纯文档变化不运行产品构建、Android sync、Gradle 或设备测试。
- 参考文档和指南描述当前产品、架构及操作方法；方案明确未实现状态；历史记录保留形成时的证据语境及可核对的处理结局。

## 停止条件

- 影响当前决定的事实找不到可靠依据时，保留该项并报告未决点。
- 事实正确、职责清楚且读者可用后停止；相邻代码偏差单独报告，不扩散为多份文档的说明，也不顺带统一无关文风或扩展产品设计。
- 本 Skill 不自动调用数据或 Android Skill；只有当前请求同时包含那些范围时才组合。
