# IronLog 文档治理

## 权威职责

先读取 [概要设计文档](../../../docs/概要设计文档.md) 的文档职责表，再只读取本次概念的权威文档和受影响引用文档。概要设计定义产品范围、模块边界、跨模块不变量和文档权威归属；Px 细化各功能域。README、[运行指南](../../../docs/如何运行IronLog.md)、[部署指南](../../../docs/部署指南.md) 和技术路线只保留各自读者完成任务所需的信息。

## 内容分类

对每项准备修改的内容先判断：

- 当前事实：必须用当前代码、配置、脚本、版本元数据或 migration 核对。
- 当前限制：描述已验证的能力边界，不把未执行验证写成结论。
- 未来规划：显式标记条件和未实现状态，不写成当前路径。
- 方法或规则：完整定义只保留在负责回答该问题的一个权威文档。

非权威文档可以保留面向其读者的必要摘要和链接，但不复制字段全集、算法、migration 矩阵、同步流程或验收矩阵。

## 修改工作流

1. 在会话内确定每项事实、规则和状态的唯一权威位置，不创建治理台账。
2. 修改概要设计时检查下游 Px 是否仍在其边界内；修改详细设计时检查是否与概要设计冲突或越权定义其他领域。
3. 同一概念需要修改多份文档时，逐份确认独立读者职责；全文搜索命中本身不是同步复制的理由。
4. 文档职责变化、合并、拆分或归档时，搜索旧职责下的相关段落和链接，处理整个职责而不是只改标题或状态。
5. 删除或迁移内容前，必须能指出接收位置、仍有效的更一般规则、当前行为证据或明确废止依据；无法证明时保留原内容。
6. 保留文档履行权威职责所需的指标、算法、决策依据和验收方法；正交化只改变位置与引用，不自行改变产品或工程语义。

## 验收

- 逐份抽查修改后的中文、标题层级、相对链接和读者语境。
- 核对代码路径、命令、版本、schema、applicationId、路由和状态等可验证事实。
- 搜索同一完整规则是否仍在多个权威位置定义，以及旧状态、旧文件名或冲突措辞是否残留。
- 执行 Skill 或仓库已有的结构检查和 `git diff --check`；纯文档变化不运行产品构建、Android sync、Gradle 或设备测试。
- 审查完整 diff，确认只改变获准的文档职责和表达，没有借文档治理改变产品行为。

## 停止条件

- 找不到可靠事实源、接收位置或废止证据时，保留内容并报告未决点，不猜测删除。
- 文档职责、链接、中文和代码事实一致后停止；不顺带统一无关文风或扩展产品设计。
- 本 Skill 不自动调用数据或 Android Skill；只有当前请求同时包含那些范围时才组合。
