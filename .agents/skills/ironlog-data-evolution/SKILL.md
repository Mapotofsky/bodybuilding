# IronLog 数据演进

## 事实源

开始前完整读取 [P2 本地文档存储与数据迁移](../../../docs/详细设计文档_P2_本地文档存储与数据迁移.md)。涉及 manifest、远端分片、合并或凭据脱敏时，再读取 [P3 WebDAV 同步与 Android 平台](../../../docs/详细设计文档_P3_WebDAV同步与Android平台.md)。领域字段语义只读取当前对象所属的 P0、P1、P6 或 P7，不在本 Skill 复制字段全集。

## 决策门

1. 明确变化属于持久化结构、持久化语义、默认目录内容，还是纯展示；纯展示不升级 schema。
2. 先确认 P2 记录的兼容基线、当前 schema、支持与拒绝范围。已有本地和 WebDAV 快照不是可丢弃 fixture。
3. 新增字段或概念前，判断现有字段能否无歧义表达；只有复用会造成语义冲突、数据丢失、非法状态或无法迁移时才新增。
4. 内置目录同-schema 内容变化必须明确选择“仅新快照生效”或定向、幂等的稳定 ID 融合；不得用初始化默认值覆盖已有目录。
5. 删除、合并、替代或重定向记录前枚举跨文档引用。重定向必须定义方向，并处理自环、循环、缺失目标与历史 ID 保留。

## 字段链路

先在 P2 的持久化链路矩阵中建立或更新该字段的唯一契约，再追踪实际受影响路径：

```text
页面输入/读取
  -> service payload 与校验
  -> core 文档类型、默认值与纯函数
  -> mapper
  -> repository mutation
  -> migration
  -> DocumentStore export/import
  -> JSON shard/manifest
  -> SyncService/WebDAV 往返
```

- 页面临时状态可以使用适合编辑的表示，但提交与所有写入口必须走同一校验和归一化路径。
- 可清空 patch 中，`undefined` 表示不修改，`null` 表示显式清空；确认 mapper、合并和序列化不折叠两者。
- repository 更新从已存文档应用受控 patch，不以页面 DTO 重建完整文档；未展示字段、预留字段和嵌套 ID 必须保留。
- WebDAV 本机端点、secret 引用、明文、密文和解密材料始终排除在同步数据之外。

## 按影响验证

只验证本次变化能影响的契约，但至少逐项判断是否需要覆盖：

- 空存储新快照、兼容范围内最旧快照、当前快照与拒绝范围快照；
- migration 重复运行的幂等性和读取后写回；
- 自定义记录、未知记录、tombstone、嵌套 ID、历史快照及未展示字段；
- `undefined`/`null`、默认值、受限枚举和非法组合；
- 删除或重定向后的引用完整性、循环与缺失目标；
- DocumentStore export/import、manifest 分片和实际受影响的 WebDAV pull/merge/backup/tmp/MOVE 往返；
- 失败时旧快照、正式数据和凭据仍可恢复，且不会触发自动清理。

优先运行现有的最近测试与确定性检查；只有缺少稳定、可观察的失败信号时才增加测试。不要把清空浏览器、AVD 或远端目录作为 migration 验证替代品。

## 停止条件

- 兼容基线、接收字段或引用策略无法确定时停止修改并报告所缺的最小决策。
- 无法证明失败不会损坏或静默丢弃已有快照时，不执行迁移、删除、覆盖或远端写入。
- 受影响链路与恢复语义通过后停止；不顺带重构无关 schema、领域模型或测试。
- 本 Skill 不自动调用 Android 或文档 Skill；只有当前请求同时包含那些范围时才组合。
